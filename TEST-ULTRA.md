# Проверка CarPlay Ultra, климат водителя

Архив содержит новые файлы и точечные изменения существующих исходников. Исходники Activities целиком не подменяются. Скрипт добавляет запись в README, сохраняет резервную копию и меняет версию на 0.1.23. Настройки подключения и сертификаты используются из вашего проекта.

1. Распакуйте содержимое архива в корень текущего VoyahPlay рядом с `gradlew.bat`.
2. Выполните из этого каталога:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\apply-ultra-pilot.ps1
   ```

3. В Android Studio выберите модуль **automotive**, вариант **debug**, соберите APK и установите поверх текущего приложения. В release этот эксперимент отсутствует. Если Android Studio собирает только один модуль, убедитесь, что зависимые `common` и `shared` тоже выбраны в варианте debug.
4. На стоянке откройте настройки главного окна VoyahPlay. В **«Диагностика» → «Ultra: проверить данные климата»** должно появиться `driverTargetC=...`, совпадающее с заданной температурой водителя. При ошибке сохраните журнал; сначала следует восстановить чтение OEM, прежде чем оценивать передачу в iPhone.
5. В **«Дополнительно»** включите **«Передавать климат водителя в iPhone»**. Нажмите **«Применить и переподключить»** / **«Переподключить сейчас»**, если появилась соответствующая панель. Настройка действует с нового подключения CarPlay; повторное открытие одного окна может сохранить старую сессию. Начните с обычного беспроводного подключения.
6. Если iPhone предложит настройку CarPlay Ultra, пройдите её и запишите результат. Отсутствие предложения также полезно: журнал покажет, какие возможности запрашивает телефон. Появление предложения само по себе ещё не подтверждает работу климата.
7. В штатном климате измените температуру водителя, например `22.0 → 22.5 → 23.0`. Между изменениями подождите несколько секунд. Посмотрите, появился ли климат на iPhone/в CarPlay и меняются ли показания. Не ждите срабатывания кнопок управления: в этой версии они не заявляются, а пришедшие запросы записи отклоняются.
8. В **«Диагностика» → «Ultra: сохранить журнал»** сохраните отчёт. В диалоге появится путь или URI. При доступном штатном экспорте файл сохраняется в папку отчётов приложения в Downloads. Пришлите файл `voyahplay-ultra-*.txt`, модель iPhone, версию iOS и результат на экране. Ничего автоматически не отправляется.

Для возврата обычного режима выключите эксперимент и примените настройки с переподключением. Удалять пару с iPhone, сертификаты или root helper для этого не требуется.

Что искать в журнале:

| Строка | Что подтверждает |
| --- | --- |
| `CAN PROBE` и `driverTargetC=...` | VoyahPlay читает заданную температуру машины |
| `INFO VSP=1` | Приложение добавило описание Vehicle State Protocol в ответ AirPlay |
| `FEATURES proposed=...vehicleStateProtocol...` | iPhone запросил этот протокол |
| `NEGOTIATED VSP=1` | Запрос телефона включён в согласованные возможности |
| `RCS CONNECTED` | iPhone подключился к каналу данных CAF |
| `CAF RX ... configRequest` | Телефон запросил описание оборудования |
| `CAF RX ... readRequest` / `registerRequest` | Телефон читает данные или подписывается |
| `CAF TX ... updateNotify` | Отправлено изменение значения; отображение подтверждается визуально |

Если есть `INFO VSP=1`, но дальше `NEGOTIATED VSP=0`, это не доказывает отсутствие разрешения Android: телефон не согласовал VSP в этой сессии. Следующий шаг выбираем по фактическим запросам, без объявления неработающих возможностей Ultra.

Для полного отката исходников используйте путь резервной копии, напечатанный скриптом:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\restore-ultra-pilot.ps1 -Backup "build\voyah-ultra-backup-YYYYMMDD-HHMMSS-xxxxxxxx"
```

Откат откажется заменять файл, который вы изменили после применения патча.
