# Проверка комплекта 0.1.23

## Исправление установщика по текущему GitHub, 2026-10-19

База: `garik345/VoyahPlay`, коммит `c991cf9e94bef8e225552915f9ecd0739d22ea85`.

- Состав пилота взят из исходного `SHA256.json`: 33 файла. Все их контрольные суммы совпали. Код этих файлов не изменялся.
- В папке `payload` обнаружены ещё 10 файлов прошлых правок интерфейса/аудио. Они не входят в список установки Ultra. В том числе текущий `VoyahControlIcon.kt` отличается от лежащего в `payload` и сохраняется.
- План из 17 точечных изменений проверен на шести актуальных исходниках репозитория. Контекст Activity обновлён под присланный и опубликованный файл.
- Модель установки на отдельной копии репозитория: 42 изменения при первом применении, 0 при повторном; все 10 текущих файлов интерфейса/аудио остались побайтно прежними.
- Проверена остановка до записи проекта при повреждении или отсутствии файла Ultra и при конфликте уже установленного файла Ultra. Проверены CRLF/LF и UTF-8 BOM для всех 33 текстовых файлов.
- Оба скрипта прошли синтаксический разбор PowerShell с LF и CRLF. Нативный Windows PowerShell в этой среде не запускался. Старое имя `apply-ultra-pilot-fix.ps1` теперь только передаёт запуск основному установщику и не пересоздаёт JSON.
- Полная CI-команда из AGENTS.md запущена и остановилась до Android-задач: не удалось скачать Java 25 с `api.foojay.io`. Полная сборка APK и lint здесь не подтверждены.
- Повторная отдельная JVM-компиляция протокола в текущей среде не завершена: локальный Android classpath неполон. Приведённые ниже 13 тестов относятся к исходной проверке пилота, а не к этому повторному запуску.

## Исходная проверка протокола 0.1.23

Проверено локально:

- Скомпилирован 71 исходник AirPlay/Ultra и необходимых зависимостей с Kotlin 2.2.10 / JVM 11. Кодеки, криптография и транспорт взяты из реальных исходников. Для обычного JVM-запуска использованы заглушки Android Log и версии платформы Android 11.
- Прошли 13 тестов: дерево CAF, доступность температуры, возраст снимка, подписки, изменения, отказ записи, неизвестные идентификаторы, неизменность обычного ответа AirPlay, согласование VSP только по запросу iPhone, зашифрованный TCP-обмен, два канала CAF и избирательное завершение потока по streamID, streamConnectionID и UUID.
- Debug-адаптер скомпилирован с реальными VoyahClient, CanSchema, VoyahValues, VoyahComfortSchema, VoyahComfortValues и DiagnosticExportStore против Android API. Для FileProvider использовалось только объявление API для компиляции; OEM Binder и экспорт на устройстве в этой среде не запускались.
- Отдельно скомпилированы основной AirPlay-код и release-фасад без debug-исходников. Классы CAF/RCS и эксперимента отсутствуют в полученном release-выводе.
- Оба изменённых Activity прошли проверку синтаксиса парсером Kotlin.
- Все восемь наборов строк разобраны XML-парсером. Новый раздел настроек отнесён только к «Дополнительно».
- Скрипты PowerShell проверены синтаксическим парсером с LF и CRLF. План точечных правок воспроизводит ожидаемые изменения и допускает повторное применение. Проверены также совместимые локальные исходники с дополнительными USB- и Bluetooth-аудиопараметрами. Нативный Windows PowerShell в этой среде не запускался.

Полная CI-команда из AGENTS.md, дополненная `:automotive:assembleDebug`, была запущена. Gradle остановился до выполнения Android-задач: среда не смогла скачать необходимую Java 25 с api.foojay.io. Полная сборка APK, lint, Android UI-тесты и проверка на iPhone не выполнены. Соберите automotive/debug на своём компьютере и выполните TEST-ULTRA.md.

Это первый эксперимент передачи данных VSP/CAF. Успешный локальный обмен не доказывает, что конкретная версия iOS согласует протокол или покажет климатический интерфейс CarPlay Ultra.
