# Кнопка трубки на руле → «Недавние» CarPlay

Обновление 3 ноября: открытие «Недавних» подтверждено на экране и короткой кнопкой.
[Постоянная настройка opack-102 и исправление requestUI](voyah-phone-wheel-20261103.md).

Обновление 2 ноября 2026: файлы KeyManager и Tweaks получены. Подготовлен
[временный тест opack-100](voyah-phone-probe-receiver-20261102.md). Постоянное назначение
кнопки пока не включено; открытие «Недавних» требует визуальной проверки на iPhone.
Ниже сохранён исходный анализ до получения этих файлов.

## Что найдено в исходниках

- В локальной копии VoyahTune, `build/pi-can-20261026/VoyahTune/Packaging/od/inject/steeringwheelkeys.js`
  и варианте `pi/inject/steeringwheelkeys.js`, кнопка PHONE имеет код **128**.
  Перехватывается `com.qinggan.keymanager.service.engine.KeyManagerReader.onKeyEvent(android.view.KeyEvent)`.
  Этот перехват расположен раньше обычного обработчика окна Android. Код 128
  нужно подтвердить на конкретной прошивке; это не стандартный Android `KEYCODE_CALL`.
- В OEM SDK из `build/cluster-return67-20261027/oem-instrument/sources/com/qinggan/system/`
  есть `KeyManager.registerInterceptListener(listener, int[] keys, int priority)`
  и парный `unregisterInterceptListener`. Публикуемая служба — `qg.key_manager`.
  Есть флаг `CB_FLAG_ALWAYS=2`, обычный приоритет 50 и фильтр кодов клавиш.
  Это предпочтительный кандидат для перехвата без замены метода Tweaks, но
  наличие клиентского API ещё не доказывает доступность регистрации нашему UID
  и нужный порядок обработки на сервере.
- `IKeyManagerService` использует синхронный Binder: регистрация перехватчика
  — транзакция 3, удаление — 4. Колбэк `IKeyManagerCallback` имеет
  `onKeyEvent(QGKeyEvent)` и `onEvent(QGKeyEvent, packageName, listenerType)`.
  SDK различает DOWN=4096, SHORT=8192, HOLD=16384, LONG=32768, UP=65536,
  HOLD_STOP=262144 и LONG_STOP=524288. Это **другой уровень событий**, чем
  Android DOWN=0 / UP=1 в обработчике VoyahTune. Смешивать их нельзя.
- В просмотренном загрузчике Tweaks `build/fullscreen-20261025/before/load.sh`
  уже запускается `keymanager.bin` в `com.qinggan.keymanager.service`.
  Самого файла текущего автомобильного перехватчика в проекте пока нет.
  Второй Frida-hook того же метода может конфликтовать с первым.
- В VoyahPlay `CarPlayCallKeys.kt` сейчас обслуживает BYD и активный звонок.
  Вне звонка `CarPlayCallKeyPolicy` пропускает событие. Ответ/сброс в
  `CarPlayController` посылает телефонный HID; команды открытия истории нет.
  Использовать ответ на звонок как замену открытия приложения нельзя.
- В `AirPlaySession.kt` уже реализована команда `showUI` для экрана карты.
  Для телефона потребуется адрес основного экрана и отдельная команда открытия
  приложения; UUID приборки для этого не подходит. Схема
  `mobilephone-recents://` встречается в открытых списках iOS URL, но её
  поддержка именно через CarPlay `showUI` в нашей сессии **не подтверждена**.

## Что предстоит проверить на машине

1. Получить настоящий KeyManager APK и текущий `keymanager.bin`, сверить версии
   и посмотреть серверную проверку прав, порядок перехватчиков и действие по
   короткому нажатию. Публичный клиентский SDK и синтетический stub VoyahTune
   не заменяют APK службы конкретной прошивки.
2. Записать одно короткое нажатие вне звонка. Установить фактический код,
   последовательность событий и компонент штатной звонилки. Отсутствие событий
   в logcat означает ограничение наблюдения, а не отсутствие кнопки.
3. Отдельно проверить открытие «Недавних» в подключённом CarPlay. Положительный
   ответ на передачу команды ещё не доказывает, что нужная вкладка открылась:
   нужен результат на экране. Команды набора/повтора номера для этого не нужны.
4. Только после этих проверок связать короткое нажатие с открытием списка.
   Пока CarPlay не подключён или функция выключена, сохранить штатную обработку.
   При входящем звонке кнопка должна отвечать через CarPlay, а открытие списка
   не должно случайно сбрасывать текущий звонок. Длительное нажатие, повторные
   события, обрыв сессии и выключение функции проверяются отдельно.

Синхронный callback кнопки должен только принять решение и поставить действие
в очередь. Сетевую отправку iPhone, запуск Activity и работу root-helper нельзя
выполнять внутри Binder-callback: это может задержать сервис кнопок. Отложенное
действие нужно привязать к той же сессии iPhone, которая была активна при нажатии.

## Готовый сборщик

`scripts/diagnostics/collect-voyah-compatibility.ps1 -WheelPhone` включает
отдельный режим. Запуск двойным щелчком подготовлен в комплекте
`Voyah-wheel-phone-1.0-with-ADB.zip`.

1. Распаковать весь ZIP, подключить автомобиль по ADB и открыть CarPlay без звонка.
2. Запустить `START.cmd`; при нескольких устройствах выбрать автомобиль.
3. Дождаться строки «Запись кнопки трубки» и нажать трубку два раза с паузой 3 с.
4. Передать новый `Voyah-compatibility-...zip` с рабочего стола и написать,
   какое окно открылось при нажатиях.

Сборщик сохраняет KeyManager/Bluetooth Phone APK, QGAPI, обработчик Tweaks,
их размеры и SHA-256. В файле событий остаются только время, код и действие;
в снимках фокуса — только имена OEM-компонентов. Полные строки журнала телефонной
службы, контакты и история звонков не записываются. Старые события logcat,
прочитанные до приглашения нажать кнопку, исключаются из новой записи.

Сборщик не регистрирует перехватчик, не очищает журнал и не изменяет автомобиль.
Пустой `wheel-events.txt` допускается и явно отмечается в отчёте. Без root
сохраняется доступная часть данных.

Сборка комплекта из проекта:

```powershell
.\scripts\diagnostics\build-voyah-compatibility-bundle.ps1 `
  -AdbDirectory 'C:\Users\ITS-Laptop\AppData\Local\Android\Sdk\platform-tools' `
  -OutputDirectory '.\build\wheel-phone-20261102\release' -WheelPhone
```

APK opack-98 и root-helper 1.2.16 этим изменением не обновлялись.
