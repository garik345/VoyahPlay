# Остановка установки helper на ПИ: RADIO_LABELS_BUSY

**Актуальное исправление — [opack-98 / установщик 1.0.2](voyah-pi-no-radio-20261102.md).**
На ПИ без приёмника обработчик не должен блокировать установку. Версия 1.0.1
ниже добавляла только повторные попытки и сохранена как история диагностики.

В полученном `voyah-root-helper.zip` два отчёта:

- Install: APK успешно прошла проверку helper 1.2.16, root подтверждён.
  Текущий APP_UID=10118, старый HELPER_SNAPSHOT_UID=10092.
  При остановке прежнего runtime получено RADIO_LABELS_BUSY=1,
  ERROR radio-agent-stop, затем supervisor/top-edge agent did not pause.
- Status: HELPER_UID_MATCH=0 и HELPER_OFFLINE / Connection refused.

Установка остановилась до замены снимка APK и allowed.uid. Поэтому новая
привязка к приложению не завершена. В этих отчётах нет отказа проверки версии
helper или сообщения о неизвестной прошивке. Статус самой radio-runtime.lock
не записан: по исходным логам нельзя отличить ещё работающего владельца от
сохранившейся неполной блокировки.

## Исправление установщика 1.0.1

Bootstrap повторяет quiesce до восьми раз с паузой в одну секунду **только**
при exit=1 и точной паре RADIO_LABELS_BUSY=1 / ERROR radio-agent-stop.
Это даёт завершиться уже запущенному дочернему обработчику радио после
остановки supervisor. Другие ошибки, включая восстановление UI радио,
идентификацию supervisor и неизвестный код выхода, не повторяются как busy.

При постоянной занятости добавляется ограниченная диагностика: метаданные
каталога, до четырёх обычных root-owned файлов владельца размером до 512 байт,
boot/PID/starttime и аргументы ещё живого владельца. Неполные и живые блокировки
не удаляются; никакой дополнительный сигнал их владельцу не отправляется.
При отказе снимок и UID остаются без замены, ложного успеха нет.

APK opack-96 и helper 1.2.16 не менялись. Обновлены bootstrap, инструкция,
метаданные установщика и контрольные суммы.

## Что сделать на этой машине

1. Закройте CarPlay и штатное радио на обоих экранах.
2. [Скачайте патч установщика](../build/helper-install97-20261102/release/VoyahPlay-installer-update-1.0.1.zip).
   Распакуйте его **четыре файла в уже существующую папку комплекта рядом
   с INSTALL.cmd**, согласившись на замену. Патч отдельно не устанавливается.
3. Выполните обычную перезагрузку мультимедиа, восстановите ADB.
4. Запустите INSTALL.cmd. Если установка попросит перезагрузить мультимедиа,
   выполните её, затем запустите STATUS.cmd.
5. Ожидается HELPER_UID_MATCH=1 и HELPER_READY=1. UID определяется заново,
   вручную прописывать 10118 не нужно. При повторной ошибке передайте свежий
   report.txt: теперь он содержит состояние блокировки.

Вместо наложения патча можно заново распаковать
[полный комплект 1.0.1](../build/helper-install97-20261102/release/VoyahPlay-opack-96-full-install-1.0.1-with-ADB.zip).
