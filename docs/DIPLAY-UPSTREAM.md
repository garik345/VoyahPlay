# Обновления CarPlay из DiPlay

Подготовлено для garik345/VoyahPlay, main `78b256f74d6a9acc79b6c1611459c8776c1c7b92` (0.1.15).
В репозитории независимая история из двух коммитов; общего предка с DiPlay нет.
Не используйте `git merge --allow-unrelated-histories` для регулярных обновлений.

## Что настроено

Workflow **DiPlay upstream review** проверяет upstream main по понедельникам в 08:17 МСК (05:17 UTC), а также запускается вручную. Время планового запуска может задерживаться на GitHub.

Базовый upstream — `4bccb39f7b866497d289cc26c4ce324585156e93` (после v0.2.13, merge PR #362). Он определён сравнением деревьев: выбранные модули совпадают, кроме изменений AndroidMediaSink/MicrophoneUplink в VoyahPlay. Исходный тег v0.2.13 не был точной базой текущего дерева.

Скрипт переносит разницу между последней принятой базой и новым upstream, применяя Git three-way к содержимому форка. Общая история репозиториев не требуется. Список путей находится в `.github/diplay-upstream.json`: протоколы, транспорт, сеть, аудио/видео, compatibility, location, JNI и соответствующие тесты в shared.

Общие Activity, ресурсы, Gradle, манифесты, hud, модули Voyah, идентификатор и название приложения не обновляются автоматически. Все upstream-изменения вне списка перечисляются в отчёте. **Они могут содержать обязательные зависимости.** Обновление ограниченного набора файлов не гарантирует совместимость и сборку.

- При чистом применении создаётся **draft PR** с исходниками, отчётом и новой базой. База в main меняется только после принятия PR.
- При конфликте исходники не меняются: PR содержит только отчёт. Патч доступен в artifact `diplay-upstream-review`. База не продвигается.
- Если изменились только исключённые пути, PR содержит отчёт и новую базу для отслеживаемого набора. Исключённые изменения остаются ручной работой, а не считаются перенесёнными.
- Пока открыт PR `automation/diplay-*`, новый PR не создаётся. Человеческие правки в ветке не перезаписываются.
- Для уже рассмотренного SHA второй PR не создаётся, даже если первый закрыт. При необходимости восстановите/переоткройте существующий PR. Для повторной генерации используйте скрипт вручную в новой ветке.
- Нет force-push, автоматического merge, публикации релиза или установки APK.

## Первое включение

1. Наложите файлы пакета на корень VoyahPlay и внесите их в main обычным коммитом/PR. Android-сборка и версия приложения от этого пакета не меняются.
2. Устраните существующий блокер `check_public_tree.py`, описанный ниже.
3. В GitHub откройте **Settings → Actions → General → Workflow permissions** и разрешите **Allow GitHub Actions to create and approve pull requests**. Workflow запрашивает `contents: write` и `pull-requests: write` только для подготовки PR; PAT не требуется. Ограничения организации могут запрещать выдачу этих прав.
4. В **Actions → DiPlay upstream review → Run workflow** выберите main.
5. Изучите draft PR и artifact. Для статуса `ready` workflow сам вызывает существующий Android checks с точным SHA кандидата. Код кандидата выполняется в отдельном job с правом contents: read, без секретов и без сохранённых Git credentials.
6. Проверьте сборку и работу на автомобиле. Только после этого переведите PR из draft и слейте вручную.

PR, созданный GITHUB_TOKEN, не запускает обычные pull_request-workflow автоматически. Поэтому проверка вызывается явно через workflow_call. Результат этой сборки виден в запуске **DiPlay upstream review**; это не гарантирует совпадение контекста required check в branch protection. При необходимости запустите **Android checks** вручную на ветке PR, и требуйте эту проверку перед слиянием. Если PR дополнялся вручную, проверять нужно новый HEAD, а не старый SHA.

## Найденный блокер в текущем репозитории

В HEAD уже отслеживаются:

- `shared/src/main/assets/offline-mfi/identity.pk8`
- `shared/src/main/assets/offline-mfi/certificate.p7b`

Существующая проверка `scripts/check_public_tree.py` запрещает эти файлы; её не отключали. Она останавливает и существующий Android CI, и новый workflow до создания ветки. Этот пакет не удаляет и не заменяет файлы аутентификации.

Сохраните рабочие файлы локально в `local-auth/offline-mfi/` (каталог уже в .gitignore). Если там есть файлы, сравните их со своей рабочей сборкой; не перезаписывайте вслепую. После сохранения удалите только отслеживание исходных файлов:

```powershell
git rm --cached -- shared/src/main/assets/offline-mfi/identity.pk8 shared/src/main/assets/offline-mfi/certificate.p7b
python scripts/check_public_tree.py
```

В пакет добавлены правила .gitignore для исходного assets-каталога, чтобы локальные копии не попали обратно в Git. Закоммитьте удаление из индекса. Локальные байты команда `--cached` оставляет на месте. Для самостоятельной сборки продолжайте использовать `DIPLAY_AUTH_ASSETS_DIR` и `assembleStandaloneDebug`, как указано в README. CI остаётся сборкой без локальной CarPlay identity.

Удаление из текущей ветки не удаляет ранее опубликованные данные из Git-истории. Если identity предназначалась для закрытого использования, её уже нельзя считать секретной; решение о замене и очистке истории нужно принимать отдельно. Новый workflow этого не делает.

## Ручная проверка и разрешение конфликта

```bash
git fetch --no-tags https://github.com/shihabal3amri/diplay.git main:refs/remotes/diplay/main
python3 scripts/prepare-diplay-update.py --dry-run
```

Нужен чистый checkout и полная история upstream с указанной базой. Dry-run не меняет индекс или рабочее дерево.

При конфликте создайте рабочую ветку, возьмите `upstream.patch` из artifact и применяйте его вручную, сохраняя наши изменения. После переноса ВСЕЙ разницы выбранных путей, исправления зависимостей и тестов измените `baseline` в JSON на Target из отчёта. Не продвигайте базу, если часть обновления пропущена: следующий запуск уже не предложит эти изменения.

Минимальная аппаратная проверка: USB/Wi-Fi, переподключение, Siri и микрофон в звонке, музыка/навигационные подсказки, стрелки и медиаданные приборки, доступ к настройкам Voyah.

## Проверка самого механизма

```bash
python3 -m unittest discover -s scripts/tests -p 'test_prepare_diplay_update.py' -v
```

Проверяются независимая история, ограничение путей, конфликт без потери локальных данных, повторно применённое изменение, dry-run и отказ на грязном рабочем дереве. Android APK этим тестом не собирается.

Проверка текущего upstream `9e244d958afe6b8fd79ade49769ce25a944f397b`: 90 изменённых путей в автоматическом наборе, 194 вне него; конфликты AndroidMediaSink.kt и MicrophoneUplink.kt. Dry-run сохранил исходники и индекс без изменений. Первый PR после устранения блокера публичного дерева будет отчётом о конфликтах, а не готовой новой CarPlay-сборкой.

## Уже объединённые аудиофайлы (исправление повторных конфликтов)

В конфигурации добавлен `reviewed_resolutions` для AndroidMediaSink.kt и MicrophoneUplink.kt. Скрипт сохраняет ручное объединение только при совпадении трёх условий: исходной базы, Git blob входящего upstream-файла и Git blob текущего файла HEAD. Если файл изменился с любой стороны, автоматическое исключение не действует — применяется обычная проверка конфликтов. Это не постоянное исключение аудиомодулей из обновлений.

После установки исправления закоммитьте его в main. Если открыт прежний draft PR только с конфликтным отчётом, закройте его без Merge. Запустите новый Run workflow на main. Имена веток должны учитывать GITHUB_SHA, как в обновлённом workflow. Ожидаемый статус для upstream 9e244d9 и проверенных аудиофайлов — ready: остальные выбранные изменения будут добавлены в draft PR, а два аудиофайла останутся прежними. Это означает применение патча, но не успешную сборку или совместимость на автомобиле.
