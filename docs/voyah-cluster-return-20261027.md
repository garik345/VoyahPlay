# Возврат карты после переключения карточек приборки — opack-67

27 октября 2026. Исправление установлено на проверенный Voyah Free RU.
Пользователь подтвердил: после обновления карта возвращается каждый раз при
2–3 переключениях между медиакарточкой и штатными статусами автомобиля.

## Симптом и причина

В `priborka.MOV` видны страницы давления в шинах и состояния автомобиля,
затем длительная штатная загрузка медиакарточки. На последующем фото — «Сб. связи».
В это время окно VoyahPlay продолжало принимать и рисовать поток 111 примерно
27–30 кадров/с. Переподключение iPhone не требовалось для восстановления потока.

Проверены APK именно этой прошивки:

- `InstrumentScreen-release-signed.apk`: штатный `ScreenActivity.onResume()`
  вызывает `syncReadyState("qg.car.cluster.MEDIA", 1)`, `onPause()` — состояние 0.
  Callback приложения отвечает на запрос показа `MEDIA_SMALL` только при
  `mediaActivityVisible=true`.
- `InstrumentClusterService-release.apk`: вызов `syncReadyState` через Binder
  обновляет `ClusterActivityState.visible` и передаёт его клиентам. Штатное
  приложение уже умеет отвечать `notifyReadyToShow(MEDIA_SMALL)` на новый запрос.

Окно нашей карты располагается над штатным ScreenActivity и ставит его на паузу.
Карта продолжает рисоваться, но штатный обработчик считает медиакарточку неготовой.
После ухода на статусы и возврата приборка ждёт подтверждения, затем показывает ошибку.
Это отдельный сбой от [положения метки и масштаба Яндекс Навигатора](voyah-cluster-live66-20261027.md).

## Диагностическая проверка

В opack-66 через временный диагностический скрипт выполнен разовый `MEDIA=1`.
Сразу изображение не появилось. Дополнительный `notifyReadyToShow` после тайм-аута
тоже не дал немедленного результата. После нового переключения страниц карта
вернулась; пользователь затем подтвердил устойчивый возврат ещё в 2–3 циклах.
Состояния OEM-приложения: `mediaActivityVisible=true`, `mediaPresentationCmd=1`.
Временные скрипты отсоединены, их файлы удалены с автомобиля.

## Изменение opack-67

После первого декодированного кадра и принятого запроса карты Activity передаёт
`MEDIA=1` через штатную Binder-службу. Перед отправкой проверяются текущий экран,
срок разрешения root-helper и принадлежность активному сеансу. Старое или закрытое
окно отменяет ещё не отправленную операцию и игнорирует запоздалый ответ.

Операция выполняется один раз для окна, с ограниченными повторами при ошибке связи.
Хеши службы приборки и QGAPI проверяются по тому же контракту RU, что используется
для вывода стрелок навигации. На непроверенной прошивке сообщение не отправляется.
Эта проверка не расширяет список поддерживаемых OEM-прошивок.

Выбор страницы остаётся штатным. Код исправления не вызывает `requestPresentation`
или `notifyReadyToShow`: на переключение водителя отвечает существующее OEM-приложение.
При закрытии карты `MEDIA=0` не отправляется: после удаления окна штатный
ScreenActivity возобновляется и сам объявляет готовность. Позднее обнуление могло бы
снова скрыть уже вернувшуюся штатную карточку.

В отчёте карты добавлены `PROBE_MEDIA_READY` и `PROBE_MEDIA_READY_REPORT`.
Настройки, геометрия карты и root-helper не менялись.

## Проверка установленной сборки

APK установлен поверх opack-66 с сохранением данных. CarPlay подключился,
в Ultra-журнале `WIRE_REV=opack-67-cluster-media-ready`, `UISYNC_NEGOTIATED=1`.
Автопоказ карты запущен на логическом дисплее 5. Зафиксированы:

```text
mapRequestAccepted=true
mediaReady=true
mediaReadyReport=MEDIA=1 sent
requested=760x616 coded=760x616
```

После этого пользователь подтвердил возвращение карты в каждом из повторных циклов
через страницы статусов. Дополнительных диагностических команд готовности после
установки opack-67 не выполнялось. Перезагрузка мультимедиа и завершение маршрута
в этой проверке не выполнялись.

Root-helper **1.2.7** подходит; переустанавливать его не нужно.

## Проверки сборки и артефакт

Прошли **475 профильных тестов**: common 184, shared 291. Пять новых проверок
покрывают готовность только после кадра, отсутствие повторных записей на кадрах,
отмену и поздний ответ, смену владельца, повтор после ошибки и закрытие без
обнуления готовности штатного окна.

20 прежних ошибок компиляции common и конфликт minSdk mobile/common. Имена отказов,
нормализованные ошибки и набор упавших задач совпали с базой opack-64, новых отличий
