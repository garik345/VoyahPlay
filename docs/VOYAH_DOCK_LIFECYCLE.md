# Левый док после запуска и возврата в VoyahPlay

Версия 1.1.2 с общим контроллером, 16.10.2026. Voyah Free 2026 RU, Android 11.

Для постоянного управления полной шириной из меню используйте новую
[инструкцию](VOYAH_TWEAKS_FULLSCREEN.md). Ниже описана отдельная проверка
скрытия дока; одновременно запускать временный тест границ и режим из APK
не нужно.

## Изменение

При переходе из `DiPlayActivity` в `CarPlayHostActivity` главное окно вызывало
`pause()`, отправляло `visible=true` и разрывало соединение QGBus. Это происходило
при внутреннем переходе между двумя окнами VoyahPlay. Предыдущее исправление
повторных запросов скрытия сохранило этот промежуточный запрос показа.

Теперь окна используют общий контроллер. Соединение привязано к контексту
приложения и передаётся новому основному окну без разрыва. Имя Activity в сообщении
обновляется для текущего окна. Старые `pause`/`destroy` не освобождают соединение
нового владельца.

В 1.1.2 `onPause` отделён от настоящего ухода. Если окно остаётся видимым под
временным OEM-окном, сохраняются соединение, скрытие дока и разрешение на ширину.
Пересоздание Activity для изменения границ при этом приостановлено до `onResume`.
`onStop`/`onDestroy` освобождают владение; периодический цикл также замечает
исчезновение ранее видимого приостановленного окна.

При настоящем уходе показ дока планируется через 750 мс. Следующее основное
окно VoyahPlay отменяет его и использует прежнее соединение. Старые callbacks
уходящего окна не меняют состояние нового владельца.

Теперь `VoyahDockVisibility` повторяет проверенный `navigation_bar_visibility`,
`visible=false`, `extra_navigation_bar_visible_type=2`:

- При возобновлении окна и подключении QGBus.
- При изменении фокуса основного окна, включая открытие/закрытие временного диалога.
- Через 300 и 1200 мс после применения настройки/получения фокуса.
- Каждые 250 мс, пока основное окно активно либо остаётся видимым под временным окном, и скрытие включено.

Повторения используют прежнее соединение, новые инъекции не устанавливаются.
Выключение настройки сразу отправляет показ и отменяет повторения.
Экран пассажира и многооконный режим исключены из скрытия. Собственные диалоги
не требуют разрыва связи. Запросы адресуются только основному экрану
(`extra_navigation_bar_visible_type=2`); управление пассажирским доком не добавляется.

Это запросы OEM, а не подтверждения состояния панели. Если процесс аварийно
завершён или принудительно остановлен, Android может не вызвать `onStop`,
и отправка восстановления не гарантируется — как и в предыдущей версии.

## Установка

1. Замените файлы с сохранением структуры каталогов.
2. Соберите выбранный вариант `automotive` и установите APK поверх текущего.
3. Включите «Настройки → Экран → Скрыть панель навигации».

Архив 1.1.2 также исправляет обновление root-помощника; порядок установки и
проверки после перезагрузки описан в [VOYAH_ROOT_HELPER.md](VOYAH_ROOT_HELPER.md).
Транспорт root-помощника не используется для скрытия через QGBus.
В актуальной версии прежний модуль удалён; автозапуск помощника описан в
[VOYAH_ROOT_HELPER.md](VOYAH_ROOT_HELPER.md).

## Проверка скрытия

Сначала проверяйте без запуска скрипта изменения границ.

| Действие | Ожидаемый результат |
| --- | --- |
| Открыть VoyahPlay с включённой настройкой | Док скрывается; возможный поздний показ лаунчером исправляется повторным запросом |
| Оставить окно на 30–60 секунд | Док остаётся скрытым |
| Перейти на штатный главный экран | Повторное скрытие прекращается, примерно через 750 мс отправляется показ дока |
| Вернуться в VoyahPlay 3–5 раз | Скрытие применяется без переключения настройки |
| Обычным способом закрыть и снова открыть VoyahPlay | Сохранённая настройка применяется снова |
| Перейти из главного окна в CarPlay, открыть настройки и вернуться | При быстром внутреннем переходе запрос показа не отправляется, соединение сохраняется |
| Изменить климат физическими кнопками и закрыть временное окно | Видимый VoyahPlay сохраняет скрытие и ширину; его Activity не перезапускается под окном климата |
| Нажимать кнопки на пассажирском экране | Повторное скрытие основного дока продолжается; пассажирский док управляется штатно |
| Выключить настройку и подождать 10 секунд | Отправляется показ дока, повторных запросов скрытия нет |

Интервал до очередного периодического запроса уменьшен с двух секунд до 250 мс.
Доставка Binder и OEM-анимация добавляют своё время. Этот механизм исправляет
секундные паузы и преждевременный собственный показ; он не перехватывает OEM show
внутри лаунчера. Если заметна короткая вспышка, сохраните журнал и короткую
видеозапись для определения следующего шага.

## Границы окна и тест Tweaks 1.1

В отчёте `20261016-173828-fa085dd0` подтверждены границы основного окна CarPlay
`0,45–1920,720` во время теста и возврат к `145,45–1920,720` после него.
Док при этом оставался видимым поверх первых 145 пикселей.

Тест 1.1 продлевает короткое разрешение только во время своего выполнения.
В конце он снимает разрешение и перезапускает собственный пакет для возврата
исходных границ. Сохранение расширения до очередной переконфигурации окна
не означает постоянного включения. Данная правка APK исправляет повторное
скрытие дока и не превращает тест границ в постоянный режим.

После проверки жизненного цикла можно повторить существующий тест 1.1 с
включённым скрытием. Заново устанавливать его payload не нужно, если версия 1.1
уже подтверждается скриптом. Верхняя OEM-строка в этой проверке сохраняется.

## Журнал, если док появляется снова

Сразу после воспроизведения выполните в PowerShell:

```powershell
adb logcat -b main -b system -d -v threadtime "VoyahDockVisibility:V" "*:S" |
    Out-File -Encoding utf8 "$env:USERPROFILE\voyahplay-dock.txt"
adb shell dumpsys window |
    Out-File -Encoding utf8 "$env:USERPROFILE\voyahplay-dock-window.txt"
```

В журнале ожидаются `QGBus connected` и `Dock request visible=false` с причинами
`connected`, `resume`, `window-focus`, `window-focus-lost`, `transition-settled` или `renew`.
`Dock owner:` показывает переход к текущему окну. При внутреннем переходе
в пределах паузы не должно быть промежуточного `visible=true reason=restore`
или нового `QGBus connected`. При настоящем уходе ожидается
`Dock restore deferred: 750 ms`, затем `visible=true reason=restore`.
Наличие записи означает отправку команды; видимость панели дополнительно
проверяется визуально и по снимку окон.

Локальная проверка: компиляция изменённого Java-класса против Android 11 API и
41 сценарий модели запуска, возврата, передачи владения, временного видимого
onPause, пассажирского экрана, потери службы и отмены отложенных команд.
Отдельно проверены 36 сценариев разрешения на ширину и отложенного пересоздания.
Полная сборка APK и испытание нового варианта на автомобиле здесь не выполнены.
