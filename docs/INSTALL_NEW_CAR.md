# Чистая установка VoyahPlay на другой автомобиль

Инструкция для локальной **automotive/debug opack-47**, root-helper **1.2.1**.
Проверенная база — Voyah Free 2026 RU, EREV, Android 11. На другой прошивке
обычный CarPlay, автомобильные службы и полноэкранный режим проверяются по отдельности.
Установку и первые экранные проверки выполняйте на стоящем автомобиле.

## 1. Подготовить компьютер и проверить автомобиль

Нужны текущий automotive APK и каталог проекта со `scripts/root-module/`,
PowerShell 5.1+ и Android platform-tools (`adb`). Если готового APK нет,
соберите `:automotive:assembleDebug` по [README](../README.md#сборка-из-исходников).
Для Ultra нужен debug: в release его реализация отключена.

Откройте PowerShell в корне проекта. Сначала найдите именно новую мультимедиа:

```powershell
$adb = 'adb' # Или полный путь к platform-tools\adb.exe
& $adb devices -l
$serial = 'SERIAL_НОВОГО_АВТОМОБИЛЯ'
$apk = (Resolve-Path '.\build\ultra-profile-20261026\voyahplay-opack-47-ultra-profile-debug.apk').Path
& $adb -s $serial shell getprop ro.build.version.sdk
& $adb -s $serial shell getprop ro.product.model
```

Если APK лежит в другом месте, замените только путь `$apk`. При подключении по сети
сначала выполните `adb connect IP:PORT`, указанные вашей мультимедиа. Не используйте
IP, serial или UID первого автомобиля. Статус ADB должен быть `device`, не `unauthorized`.

Для разделов с root требуется уже имеющийся доступ:

```powershell
& $adb -s $serial shell su 0 id
```

Ожидается `uid=0(root)`. Root-helper не получает root сам. Если доступа нет,
можно установить и проверить обычный CarPlay и профиль Ultra; установку helper пропустите.

**Условия полного экрана.** На новой машине должны совпадать проверенные
компоненты Tweaks 1.1 и прошивки.

1.1 — версия установленной добавки/моста полной ширины, не версия самого VoyahTweaks.
**Установщик этой добавки не входит в VoyahPlay.** Если на машине её нет, сначала
нужна совместимая подготовка стороннего моста; из одного APK и root-helper этот
этап не воспроизводится. До неё используйте обычное окно и пропустите разделы 5–6.

Сверьте файлы чтением:

```powershell
& $adb -s $serial shell su 0 sha256sum /system/etc/init.logcat.sh /system/framework/services.jar /data/local/tmp/ss11.bin /data/local/tmp/frida-inject /system/priv-app/SystemUI-release-signed/SystemUI-release-signed.apk
```

| Файл | SHA-256 текущей поддерживаемой конфигурации |
| --- | --- |
| `init.logcat.sh`, до первой установки helper | `a2153c1819c2eb15a0a3c7264ed90c81120b61214a1e891d798a0289551666bb` |
| `services.jar` | `0faed7ebf1094c62a4f92b4bc533bbb3c08480a2cd847567cb1cff91b2d1d045` |
| `ss11.bin` | `575735ed6f6074f1c33483c8df5c8984e51e6dc0fba328b1e4179ca10b9f9d7d` |
| `frida-inject` | `0d99be0e44d4ca3449056fa0a0b868fca1cf66c8ad704508949945afc07706aa` |
| `SystemUI-release-signed.apk` | `28f5d93eaec22b755b339193a733bd0d4160c496cf301bcd2fcfb88c36ade162` |

После установки helper хеш `init.logcat.sh` закономерно меняется; его состояние
проверяет установщик по сохранённому оригиналу. Для **чистой** машины несовпадение
или отсутствие файлов означает, что этот путь полного экрана пока не подтверждён.
Root-helper не устанавливает Tweaks, injector и их сторонние условия работы.
При `BOOT_HOOK_UNREVIEWED`, `BOOT_HOOK_CHANGED` или `TWEAKS_FILES_CHANGED`
сохраните отчёт для адаптации прошивки; не заменяйте файлы прошивки файлами другой машины.

## 2. Установить APK и открыть приложение

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath $apk
& $adb -s $serial install -r $apk
if ($LASTEXITCODE -ne 0) { throw 'APK не установлен: прочитайте ошибку ADB.' }
& $adb -s $serial shell am start -n com.shilapi.xcertplay/.DiPlayActivity
```

SHA-256 подготовленного opack-47:
`23801c464239ad0639578d55c58217e907179a97bf04c0044e41bbbb6c71f2d8`.
У собственной пересборки будет другая сумма.

Приложение устанавливается для основного пользователя Android. При чистой установке
оно получит собственные настройки, идентичность приёмника и UID. Не копируйте
`shared_prefs`, сопряжения, `/data/local/voyahplay-root-helper` или `allowed.uid`
из первого автомобиля. На новой машине установщик сам определяет UID.

Если `install -r` сообщает о другой подписи уже установленного приложения,
это не чистая установка. Для обновления нужен APK с той же подписью.
Удаление приложения стирает его данные и меняет привязку helper; не используйте
удаление как автоматический способ исправить ошибку подписи.

## 3. Проверить обычное подключение iPhone

1. Откройте «Настройки → Подключение» и настройку подключения iPhone.
2. Для текущей конфигурации используется **локальная офлайн-аутентификация MFi**.
   При собственной сборке должны быть добавлены соответствующие runtime assets;
   установка helper отсутствующие MFi assets не заменяет.
3. Для беспроводного режима выберите встроенную точку доступа автомобиля.
   Включите её в штатных настройках, выберите 5 ГГц, если доступно, и точно
   укажите её имя и пароль в VoyahPlay. Для проводного режима выберите USB.
4. Выдайте запрошенные Android-разрешения. На iPhone включите Bluetooth и Wi-Fi,
   выберите его в мастере VoyahPlay и разрешите CarPlay, когда появится запрос.
5. Сначала добейтесь обычного изображения CarPlay и звука; затем переходите к Ultra.

Автоматизация состоит из разных настроек:

| Цель | Где включать |
| --- | --- |
| Открывать VoyahPlay после загрузки автомобиля | «Подключение → Автозапуск при загрузке» |
| Подключаться при открытии VoyahPlay | «Подключение → Подключаться при открытии» |
| Поднимать сохранённую точку доступа | Настройка точки доступа в «Подключение»; нужен разрешённый системой доступ к её управлению |
| Поднимать root-helper после загрузки | «Дополнительно → Root-помощник VoyahPlay → Автозапуск root-помощника» |

В новом профиле автозапуск приложения выключен. Включайте нужные варианты явно.
Автозапуск helper не открывает VoyahPlay и не подключает iPhone.
В opack-46 временные ошибки запуска получают медленные автоматические повторы;
выключенная точка доступа ожидает фактического включения на открытом экране подключения.

## 4. Профиль CarPlay Ultra

В приложении включите «Дополнительно → CarPlay Ultra: климат и комфорт →
Климат и комфорт через CarPlay Ultra». **MFi4 включается вместе с этим переключателем**;
отдельной кнопки MFi4 больше нет. На машине без радиоприёмника выключите «Радио».

С opack-47 профиль объявляется самим приложением вместе с общим переключателем:
MFi4, тема Ultra, идентификаторы экрана и описание панелей включаются совместно.
**ADB-команды, редактирование XML и root-helper для включения профиля не нужны.**
Настройка применяется при следующем подключении; если CarPlay работает, используйте
предложенную приложением команду переподключения.

Профиль использует тот же диагностический пример LIVI `44C9FA31EC:985:19.0`,
который проверен на рабочем автомобиле. Это не собственная тема Voyah; пакет
ресурсов темы не включён в APK, поэтому совместимость другого iPhone/iOS проверяется
отдельно. [Почему объявление темы понадобилось](ultra-bootstrap-20261024.md).

Подключите iPhone заново. В журнале Ultra проверьте `WIRE_REV=opack-47-ultra-profile`,
`MUTUAL_AUTH=true`, `ULTRA_PROFILE=integrated`, `THEME_PROBE=true`, `ASSET_PROBE=false`
и CAF CONFIG. `THEME_PROBE` — сохранённое имя диагностической строки; отдельного
пользовательского параметра теперь нет. Ожидаются «Климат» и «Автомобиль»; радио
зависит от его настройки и наличия OEM-службы. Описание логической панели само по
себе не выводит видеокарту на физическую приборку.

Чтобы вернуться к обычному CarPlay, выключите общий переключатель Ultra и
переподключитесь. Тема, MFi4 и CAF/UI Sync выключатся вместе. Старые `themeProbe`,
`panelProbe` и `mutualAuth` удаляются миграцией и не влияют на работу даже при
восстановлении прежнего файла настроек. Выбор радио, размер и сопряжения сохраняются.

**Доступ к автомобилю.** В «Диагностика → Ultra: проверить данные климата» проверьте
чтение OEM-данных. Управлению нужен `com.qinggan.permission.WRITE_CANBUS` и совпадение
проверенной версии CAN-службы. В проекте нет универсального установщика этого
OEM-разрешения. Если текущая прошивка допускает его выдачу через PackageManager:

```powershell
& $adb -s $serial shell su 0 pm grant com.shilapi.xcertplay com.qinggan.permission.WRITE_CANBUS
```

После команды повторно проверьте доступ в отчёте и обратное чтение команды.
Ошибки `not a changeable permission`, `Unknown permission` и несовпадение OEM APK
требуют отдельной адаптации этой прошивки; наличие root-helper не означает доступ CAN.

## 5. Установить root-helper 1.2.1

Продолжайте этот этап после проверки совместимости файлов в пункте 1.
Отключите полноэкранные опции в VoyahPlay на время установки.
Из корня текущего проекта выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\root-module\root-helper.ps1 -Mode Install -Serial $serial -Adb $adb
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\root-module\root-helper.ps1 -Mode Status -Serial $serial -Adb $adb
```

Установщик берёт **установленный APK этого автомобиля**, создаёт приватную копию,
сам находит UID, устанавливает supervisor и обработчики верхней границы/SystemUI,
добавляет автозапуск в проверенный `/system/etc/init.logcat.sh` с резервной копией.
Готовый каталог помощника с другой машины сюда не подходит.

В результате ожидаются:

```text
HELPER_VERSION=1.2.1
HELPER_READY=1
CAPABILITIES=TWEAKS_BOUNDS_1_1
AUTOSTART_INSTALLED=1
AUTOSTART_ENABLED=1
```

При первой установке автозапуск включается. При обновлениях сохраняется его выбор.
`HELPER_READY=1` подтверждает сам помощник; работоспособность Tweaks и скрытия
панелей проверяется отдельно на следующем этапе.

Если есть `REBOOT_REQUIRED=1` или `BOOT_MOUNT_READ_ONLY=0`, после успешной записи
выполните обычную перезагрузку мультимедиа. После неё повторите `-Mode Status`;
ожидаются `BOOT_MOUNT_READ_ONLY=1`, `BOOT_RESULT=ready`, `BOOT_HELPER_VERSION=1.2.1`.
BOOT-поля появляются именно после загрузки с установленным автозапуском.

## 6. Включить полный экран и проверить результат

1. В «Дополнительно → Root-помощник VoyahPlay» откройте «Состояние root-помощника
   и автозапуска», проверьте совместимую 1.2.1 и включённый автозапуск.
2. В «Экран» включите скрытие нижней/навигационной панели — на Voyah это левый док.
   Оно связано с управлением полной шириной через helper/Tweaks.
3. Включите скрытие верхней панели. Для расширения вверх нужны оба обработчика
   helper и готовая ширина. Проверяйте отчёт окна: `TWEAKS_BOUNDS_READY=1`,
   `BRIDGE_ACK=1`, а при верхнем расширении — `TOP_BOUNDS_READY=1`, `STATUS_BAR_READY=1`.
4. Для штатного окна 1920×720 ожидается расширение до 0,0–1920,720;
   контент отступает от ручек шторок на 3 px, начинаясь с 19,19 при 160 dpi.
5. В «Экран → Размер CarPlay» выберите подходящий масштаб. «Очень маленький»
   передаёт 400 мм; на проверенном телефоне он дал три строки приложений.
   Подтвердите применение и переподключение, если оно предлагается.
6. Проверьте касания по краям, обе шторки, возврат штатных панелей вне VoyahPlay,
   переключение приложения на пассажирском экране и вход
   **«Автомобиль → Настройки VoyahPlay»** со скрытым доком.

Отключите компьютер и проверьте обычную перезагрузку мультимедиа. Отдельно проверьте
следующий запуск после длительной стоянки. Вызов и микрофон проверяйте разговором
с человеком; радио — также со штатного пассажирского приложения. Для климатических
проверок запомните исходные значения и верните их после проверки.

## 7. Обновление и восстановление

Обычное обновление: `install -r` APK с той же подписью. Совместимый helper 1.2.1
после каждого APK переустанавливать не требуется. При переходе с 1.1.2/1.2.0,
изменении его версии или несовместимости повторите `-Mode Install`, затем `-Mode Status`.

| Задача | Режим root-helper.ps1 |
| --- | --- |
| Прочитать состояние | `Status` |
| Запустить уже установленный helper вручную | `Start` |
| Включить/выключить будущий автозапуск | `EnableAutoStart` / `DisableAutoStart` |
| Остановить текущие собственные процессы | `Stop` |
| Восстановить оригинальный boot-сценарий из проверенной копии | `RemoveAutoStart` |

В командах сохраняйте `-Serial $serial -Adb $adb`. Выключение автозапуска действует
на следующие загрузки. Перед остановкой отключите полноэкранные опции в приложении.
`Stop` не удаляет boot-entry: при включённом автозапуске helper вернётся после загрузки.
Для завершения отката также выполните `RemoveAutoStart`; приватные backup/журналы
вручную удалять не нужно. Подробности — [VOYAH_ROOT_HELPER.md](VOYAH_ROOT_HELPER.md).

Если шаг не подтверждён, сохраните отчёт скрипта
`build/voyah-root-helper/<запуск>/report.txt`, отчёт окна и диагностику приложения.
При отсутствии кнопок Ultra сначала проверяйте тему и MFi4; при отсутствии управления —
WRITE_CANBUS и OEM-совместимость; при отсутствии полного экрана — helper и мост Tweaks.
