# Чистая установка VoyahPlay на другой автомобиль

Для проверенной ПИ OTA7.2 build 35 добавлен комплект opack-75/helper 1.2.10: [поддержка этой прошивки и установка двойным щелчком](voyah-pi-ota72-20261028.md).

Инструкция для локальной **automotive/debug opack-72**, root-helper **1.2.9**.

Если прошивка ПИ ещё не изучена и климат/helper отклоняют её, сначала используйте
[сборщик совместимости с ADB и START.cmd](VOYAH_COMPATIBILITY_COLLECTOR.md).
Он сохраняет отчёт и файлы для добавления поддержки без изменения машины.
Дополнения opack-68–70 подготовлены без автомобиля;
аппаратно проверена opack-67.
[Готовые и оставшиеся пункты Ultra](ultra-audio-drive-20261027.md).
Проверенная база — Voyah Free 2026 RU, EREV, Android 11. На другой прошивке
обычный CarPlay, автомобильные службы и полноэкранный режим проверяются по отдельности.
Установку и первые экранные проверки выполняйте на стоящем автомобиле.

## 1. Подготовить компьютер и проверить автомобиль

Нужны текущий automotive APK и каталог проекта со `scripts/root-module/`,
PowerShell 5.1+ и Android SDK Platform-Tools (`adb.exe`). Если готового APK нет,
соберите `:automotive:assembleDebug` по [README](../README.md#сборка-из-исходников).
Для Ultra нужен debug: в release его реализация отключена.

### Подготовить ADB в Windows

`adb.exe` не входит в Windows или APK VoyahPlay. В готовом
[ZIP установщика root-helper](../build/pi-dock72-20261028/release-final/helper/VoyahPlay-root-helper-1.2.9-with-ADB.zip)
ADB уже находится внутри. Для команд ниже, выполняемых из исходников проекта,
его нужно подготовить отдельно.
Если команда `adb` не найдена, файл может отсутствовать либо его папка не добавлена в `PATH`.

- Если установлен Android Studio, используйте `adb.exe` из папки SDK `platform-tools`.
  Обычный путь — `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`;
  фактический путь SDK указан в Android Studio → SDK Manager. Если компонента нет,
  установите **Android SDK Platform-Tools** там же.
- Если Android Studio нет, скачайте **SDK Platform-Tools for Windows**
  с [официальной страницы Android](https://developer.android.com/tools/releases/platform-tools).
  Распакуйте весь архив, например в `C:\Tools`, чтобы получился файл
  `C:\Tools\platform-tools\adb.exe`. Сохраните остальные файлы пакета рядом с ним.

Добавлять ADB в `PATH` необязательно: дальше используется полный путь в переменной `$adb`,
а root-helper получает его через `-Adb`. Скрипт сам ADB не скачивает.
Откройте PowerShell в корне проекта и выполните:

```powershell
$adb = (Get-Command adb -CommandType Application -ErrorAction SilentlyContinue |
    Select-Object -First 1 -ExpandProperty Source)
if (-not $adb) { $adb = Join-Path $env:LOCALAPPDATA 'Android\Sdk\platform-tools\adb.exe' }
if (-not (Test-Path -LiteralPath $adb -PathType Leaf)) { $adb = 'C:\Tools\platform-tools\adb.exe' }
if (-not (Test-Path -LiteralPath $adb -PathType Leaf)) {
    throw 'ADB не найден. Установите Platform-Tools и укажите полный путь к adb.exe в $adb.'
}
& $adb version
```

Если распаковали пакет или установили SDK в другую папку, задайте свой полный путь
в `$adb` перед проверкой `version`. Путь с пробелами также подходит.

### Выбрать мультимедиа, если устройств несколько

Сначала посмотрите список:

```powershell
& $adb devices -l
```

**Serial нужно указывать, если ADB видит больше одного устройства** — например,
автомобиль и телефон, эмулятор либо одну мультимедиа одновременно по USB и сети.
Скопируйте идентификатор нужной мультимедиа из первого столбца списка; при сетевом
подключении это может быть `IP:PORT`. Он передаётся как `-s` в ADB и `-Serial` в root-helper.
**Если устройство одно, serial не требуется:** оставьте `$serial = $null` в следующем блоке.

При подключении по сети сначала выполните `& $adb connect 'IP:PORT'` с адресом
вашей мультимедиа, затем повторите `& $adb devices -l`. Не используйте IP, serial
или UID первого автомобиля. Нужная строка должна иметь статус `device`.
Если список пуст, проверьте подключение и отладку ADB; при `unauthorized` подтвердите
доступ на мультимедиа, при `offline` восстановите соединение. Указание serial эти состояния не исправляет.

Выполните следующий блок и остальные команды инструкции в том же окне PowerShell:

```powershell
$serial = $null # Одно устройство: менять не нужно.
# Только если устройств несколько, раскомментируйте и заполните следующую строку:
# $serial = 'SERIAL_НОВОГО_АВТОМОБИЛЯ'
$adbTarget = @()
$helperTarget = @()
if ($serial) {
    $adbTarget = @('-s', $serial)
    $helperTarget = @('-Serial', $serial)
}
$apk = (Resolve-Path '.\build\pi-dock72-20261028\voyahplay-opack-72-pi-dock-debug.apk').Path
& $adb @adbTarget shell getprop ro.build.version.sdk
& $adb @adbTarget shell getprop ro.product.model
```

Если APK лежит в другом месте, замените путь `$apk`. Массивы `@adbTarget` и `@helperTarget`
добавляют выбор устройства только при заполненном `$serial`. Если состав подключённых
устройств изменился, повторите выбор и этот блок перед следующими командами.

Для разделов с root требуется уже имеющийся доступ:

```powershell
& $adb @adbTarget shell su 0 id
```

Ожидается `uid=0(root)`. Root-helper не получает root сам. Если доступа нет,
можно установить и проверить обычный CarPlay и профиль Ultra; установку helper пропустите.

**Условия полного экрана.** На новой машине должны совпадать проверенные
компоненты Tweaks 1.1 и прошивки.

1.1 — версия установленной добавки/моста полной ширины, не версия самого VoyahTweaks.
Для полученной прошивки ПИ подготовлен [отдельный комплект с APK, ADB и добавкой](voyah-pi-fullscreen-20261028.md).
Его INSTALL.cmd сначала проверяет точную пару файлов этой прошивки, затем ставит
APK, добавку с резервной копией и helper. После этого нужна перезагрузка мультимедиа.
Обычный установщик helper добавку не ставит. На остальных неподготовленных машинах
нужна отдельная проверка совместимости; до неё используйте обычное окно.

Сверьте файлы чтением:

```powershell
& $adb @adbTarget shell su 0 sha256sum /system/etc/init.logcat.sh /system/framework/services.jar /data/local/tmp/ss11.bin /data/local/tmp/frida-inject /system/priv-app/SystemUI-release-signed/SystemUI-release-signed.apk
```

| Файл | SHA-256 текущей поддерживаемой конфигурации |
| --- | --- |
| `init.logcat.sh`, до первой установки helper | `a2153c1819c2eb15a0a3c7264ed90c81120b61214a1e891d798a0289551666bb` |
| `services.jar` | `0faed7ebf1094c62a4f92b4bc533bbb3c08480a2cd847567cb1cff91b2d1d045` |
| `ss11.bin` | `575735ed6f6074f1c33483c8df5c8984e51e6dc0fba328b1e4179ca10b9f9d7d` |
| `frida-inject` | `0d99be0e44d4ca3449056fa0a0b868fca1cf66c8ad704508949945afc07706aa` |
| `SystemUI-release-signed.apk` | `28f5d93eaec22b755b339193a733bd0d4160c496cf301bcd2fcfb88c36ade162` |

После установки helper хеш `init.logcat.sh` закономерно меняется; его состояние
проверяет установщик по сохранённому оригиналу. Для **чистой** машины несовпадение
или отсутствие файлов означает, что этот путь полного экрана пока не подтверждён.
Root-helper не устанавливает Tweaks, injector и их сторонние условия работы.
При `BOOT_HOOK_UNREVIEWED`, `BOOT_HOOK_CHANGED` или `TWEAKS_FILES_CHANGED`
сохраните отчёт для адаптации прошивки; не заменяйте файлы прошивки файлами другой машины.

## 2. Установить APK и открыть приложение

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath $apk
& $adb @adbTarget install -r $apk
if ($LASTEXITCODE -ne 0) { throw 'APK не установлен: прочитайте ошибку ADB.' }
& $adb @adbTarget shell am start -n com.shilapi.xcertplay/.DiPlayActivity
```

SHA-256 подготовленного opack-72:
`4ed5f68dfda5bb82630f0a2e8eda58f8c83494f014edd6b1659b0777fd2b34bb`.
У собственной пересборки будет другая сумма.

Приложение устанавливается для основного пользователя Android. При чистой установке
оно получит собственные настройки, идентичность приёмника и UID. Не копируйте
`shared_prefs`, сопряжения, `/data/local/voyahplay-root-helper` или `allowed.uid`
из первого автомобиля. На новой машине установщик сам определяет UID.

Если `install -r` сообщает о другой подписи уже установленного приложения,
это не чистая установка. Для обновления нужен APK с той же подписью.
Удаление приложения стирает его данные и меняет привязку helper; не используйте
удаление как автоматический способ исправить ошибку подписи.

## 3. Проверить обычное подключение iPhone

1. Откройте «Настройки → Подключение» и настройку подключения iPhone.
2. Для текущей конфигурации используется **локальная офлайн-аутентификация MFi**.
   При собственной сборке должны быть добавлены соответствующие runtime assets;
   установка helper отсутствующие MFi assets не заменяет.
3. Для беспроводного режима выберите встроенную точку доступа автомобиля.
   Включите её в штатных настройках, выберите 5 ГГц, если доступно, и точно
   укажите её имя и пароль в VoyahPlay. Для проводного режима выберите USB.
4. Выдайте запрошенные Android-разрешения. На iPhone включите Bluetooth и Wi-Fi,
   выберите его в мастере VoyahPlay и разрешите CarPlay, когда появится запрос.
5. Сначала добейтесь обычного изображения CarPlay и звука; затем переходите к Ultra.

Автоматизация состоит из разных настроек:

| Цель | Где включать |
| --- | --- |
| Открывать VoyahPlay после загрузки автомобиля | «Подключение → Автозапуск при загрузке» |
| Подключаться при открытии VoyahPlay | «Подключение → Подключаться при открытии» |
| Поднимать сохранённую точку доступа | Настройка точки доступа в «Подключение»; нужен разрешённый системой доступ к её управлению |
| Поднимать root-helper после загрузки | «Дополнительно → Root-помощник VoyahPlay → Автозапуск root-помощника» |

В новом профиле автозапуск приложения выключен. Включайте нужные варианты явно.
Автозапуск helper не открывает VoyahPlay и не подключает iPhone.
В opack-46 временные ошибки запуска получают медленные автоматические повторы;
выключенная точка доступа ожидает фактического включения на открытом экране подключения.

## 4. Профиль CarPlay Ultra

В приложении включите «Дополнительно → CarPlay Ultra: климат и комфорт →
Климат и комфорт через CarPlay Ultra». **MFi4 включается вместе с этим переключателем**;
отдельной кнопки MFi4 больше нет. На машине без радиоприёмника выключите «Радио».

С opack-47 профиль объявляется самим приложением вместе с общим переключателем:
MFi4, тема Ultra, идентификаторы экрана и описание панелей включаются совместно.
**ADB-команды, редактирование XML и root-helper для включения профиля не нужны.**
Настройка применяется при следующем подключении; если CarPlay работает, используйте
предложенную приложением команду переподключения.

Профиль использует тот же диагностический пример LIVI `44C9FA31EC:985:19.0`,
который проверен на рабочем автомобиле. Это не собственная тема Voyah; пакет
ресурсов темы не включён в APK, поэтому совместимость другого iPhone/iOS проверяется
отдельно. [Почему объявление темы понадобилось](ultra-bootstrap-20261024.md).

Подключите iPhone заново. В журнале Ultra проверьте `WIRE_REV=opack-72-pi-dock`,
`MUTUAL_AUTH=true`, `ULTRA_PROFILE=integrated`, `THEME_PROBE=true`, `ASSET_PROBE=false`
и CAF CONFIG. `THEME_PROBE` — сохранённое имя диагностической строки; отдельного
пользовательского параметра теперь нет. Ожидаются «Климат» и «Автомобиль»; радио
зависит от его настройки и наличия OEM-службы. Описание логической панели само по
себе не выводит видеокарту на физическую приборку.

Чтобы вернуться к обычному CarPlay, выключите общий переключатель Ultra и
переподключитесь. Тема, MFi4 и CAF/UI Sync выключатся вместе. Старые `themeProbe`,
`panelProbe` и `mutualAuth` удаляются миграцией и не влияют на работу даже при
восстановлении прежнего файла настроек. Выбор радио, размер и сопряжения сохраняются.

**Доступ к автомобилю.** В «Диагностика → Ultra: проверить данные климата» проверьте
чтение OEM-данных. Управлению нужен `com.qinggan.permission.WRITE_CANBUS` и совпадение
проверенной версии CAN-службы. В проекте нет универсального установщика этого
OEM-разрешения. Если текущая прошивка допускает его выдачу через PackageManager:

```powershell
& $adb @adbTarget shell su 0 pm grant com.shilapi.xcertplay com.qinggan.permission.WRITE_CANBUS
```

После команды повторно проверьте доступ в отчёте и обратное чтение команды.
Ошибки `not a changeable permission`, `Unknown permission` и несовпадение OEM APK
требуют отдельной адаптации этой прошивки; наличие root-helper не означает доступ CAN.

## 5. Установить root-helper 1.2.9

Продолжайте этот этап после проверки совместимости файлов в пункте 1.
Отключите полноэкранные опции в VoyahPlay на время установки.
В Windows можно использовать
[готовый ZIP с ADB](../build/pi-dock72-20261028/release-final/helper/VoyahPlay-root-helper-1.2.9-with-ADB.zip):
распакуйте его целиком и дважды нажмите **INSTALL.cmd**. Установщик предложит выбрать
автомобиль при нескольких устройствах и сам выполнит Install, затем Status.
Для повторной проверки после перезагрузки используйте **STATUS.cmd**.
Уже установленный APK VoyahPlay, root и совместимые Tweaks/injector нужны заранее;
архив их не устанавливает. Исходники проекта для запуска этого комплекта не нужны.

Вариант с командами из исходников:
Из корня текущего проекта выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\root-module\root-helper.ps1 -Mode Install -Adb $adb @helperTarget
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\root-module\root-helper.ps1 -Mode Status -Adb $adb @helperTarget
```

Установщик берёт **установленный APK этого автомобиля**, создаёт приватную копию,
сам находит UID, устанавливает supervisor и обработчики верхней границы/SystemUI,
добавляет автозапуск в проверенный `/system/etc/init.logcat.sh` с резервной копией.
Готовый каталог помощника с другой машины сюда не подходит.

В результате ожидаются:

```text
HELPER_VERSION=1.2.9
HELPER_READY=1
CAPABILITIES=TWEAKS_BOUNDS_1_1
RADIO_LABELS_CAPABILITY=OEM_RADIO_LABELS_1
CLUSTER_PROBE_CAPABILITY=VOYAH_CLUSTER_PROBE_1
CLUSTER_AUTO_CAPABILITY=VOYAH_CLUSTER_AUTO_1
RADIO_LABELS_ENABLED=0
AUTOSTART_INSTALLED=1
AUTOSTART_ENABLED=1
```

При первой установке автозапуск включается. При обновлениях сохраняется его выбор.
`HELPER_READY=1` подтверждает сам помощник; работоспособность Tweaks и скрытия
панелей проверяется отдельно на следующем этапе.

Если есть `REBOOT_REQUIRED=1` или `BOOT_MOUNT_READ_ONLY=0`, после успешной записи
выполните обычную перезагрузку мультимедиа. После неё повторите `-Mode Status`;
ожидаются `BOOT_MOUNT_READ_ONLY=1`, `BOOT_RESULT=ready`, `BOOT_HELPER_VERSION=1.2.9`.
BOOT-поля появляются именно после загрузки с установленным автозапуском.

## 6. Включить полный экран и проверить результат

1. В «Дополнительно → Root-помощник VoyahPlay» откройте «Состояние root-помощника
   и автозапуска», проверьте совместимую 1.2.9 и включённый автозапуск.
2. В «Экран» включите скрытие нижней/навигационной панели — на Voyah это левый док.
   Оно связано с управлением полной шириной через helper/Tweaks.
3. Включите скрытие верхней панели. Для расширения вверх нужны оба обработчика
   helper и готовая ширина. Проверяйте отчёт окна: `TWEAKS_BOUNDS_READY=1`,
   `BRIDGE_ACK=1`, а при верхнем расширении — `TOP_BOUNDS_READY=1`, `STATUS_BAR_READY=1`.
4. Для штатного окна 1920×720 ожидается расширение до 0,0–1920,720;
   контент отступает от ручек шторок на 3 px, начинаясь с 19,19 при 160 dpi.
5. В «Экран → Размер CarPlay» выберите подходящий масштаб. «Очень маленький»
   передаёт 400 мм; на проверенном телефоне он дал три строки приложений.
   Подтвердите применение и переподключение, если оно предлагается.
6. Проверьте касания по краям, обе шторки, возврат штатных панелей вне VoyahPlay,
   переключение приложения на пассажирском экране и вход
   **«Автомобиль → Настройки VoyahPlay»** со скрытым доком.

Отключите компьютер и проверьте обычную перезагрузку мультимедиа. Отдельно проверьте
следующий запуск после длительной стоянки. Вызов и микрофон проверяйте разговором
с человеком; радио — также со штатного пассажирского приложения. Для климатических
проверок запомните исходные значения и верните их после проверки.

## 7. Названия станций в штатном радио

Этот шаг необязателен и не влияет на включение CarPlay Ultra. Патч выключен по
умолчанию. Он рассчитан на проверенный APK `com.pateo.rdsapp`, Android 11 и уже
имеющийся совместимый `/data/local/tmp/frida-inject`. Эти компоненты helper не
устанавливает; при несовпадении APK/инструмента включение будет отклонено.

После установки helper 1.2.2 включите «Дополнительно → Root-помощник VoyahPlay →
Названия станций в штатном радио (экспериментально)» и откройте штатное радио.
В двух списках имя из RDS должно появиться над частотой. Если имени нет, остаётся
исходная частота; длинное имя сокращается многоточием. Переподключать CarPlay не нужно.
Патч не заменяет APK радио и не меняет приёмник. Проверка настоящих экранов пока
предстоит. Для отката выключите этот же переключатель и дождитесь восстановления
подписей. [Совместимость, диагностика и план проверки](oem-radio-labels-20261026.md).

## 8. Карта на приборке (экспериментально)

Для автоматического вывода нужны opack-64 или новее и root-helper 1.2.7. Если установлен
helper 1.2.6 или более ранний, после APK один раз обновите помощник из текущих
исходников. Для текущей opack-72 установите 1.2.9 один раз после APK; после этого повторять установку не нужно. В статусе ожидается
`CLUSTER_AUTO_CAPABILITY=VOYAH_CLUSTER_AUTO_1`. С helper 1.2.5 ручные тесты и полный
экран сохраняются, но автоматические команды не принимаются.

В «Дополнительно → Карта на приборке (экспериментально)» включите «Карта CarPlay
на приборной панели (экспериментально)» и подтвердите переподключение. При активном
маршруте карта должна появляться автоматически и оставаться дольше минуты.
Завершение маршрута, отключение iPhone или выключение настройки закрывает окно
и возвращает штатную медиакарточку. После повторного подключения и начала маршрута
приложение снова запрашивает вывод. Ultra, климат и автомобиль сохраняются.

В opack-61 карта запрашивается под форму медиакарточки 574×464, чтобы заполнить её
высоту. Здесь же появились два управления масштабом:

- «Надписи и значки карты» — 75%, 100%, 125% или 150%. Больше процент — крупнее
  элементы. Выберите значение, нажмите «Сохранить», затем «Переподключить сейчас».
  Изменение не прерывает сеанс само; размер основного экрана CarPlay не меняется.
- «Приблизить карту» и «Отдалить карту» — по одному шагу для уже открытой карты
  приборки, без переподключения. iPhone может сам корректировать приближение во
  время навигации; последнее положение этих кнопок отдельно не сохраняется.

Кнопки «Показать карту CarPlay» и «Показать тестовую сетку» оставлены для ручной
проверки на 60 секунд. В обычной работе их нажимать не требуется. Ручная проверка
или «Остановить тест» приостанавливает автопоказ до завершения текущего маршрута
либо переподключения iPhone; для следующей проверки начните новый маршрут.

Геометрия и видеокарта Apple «Карт» с Ultra проверены на машине в opack-59.
Полная высота карты и увеличение надписей при 125% подтверждены на автомобиле.
В opack-63/helper 1.2.7 исправлено продление окна на Android 11 и отключение CarPlay
при удалении вспомогательной задачи. В opack-64 исправлен запрос показа карты
и кнопки приближения: они проверяют токен основного потока текущего подключения.
В Яндекс Навигаторе видимый эффект zoom не подтверждён. В Apple «Картах» приближение
и обратное отдаление проверены по короткой серии снимков. Диагностика opack-65
входит в текущую сборку. Helper остаётся 1.2.7.
[Результаты аппаратной проверки и текущий APK](voyah-cluster-live-20261027.md).

В opack-66 карта и её зеркала декодируются с размерами потока 111. Ранее для
инициализации использовался размер основного экрана. На машине размеры совпали;
метка Apple «Карт» около центра, у Яндекс Навигатора остаётся правее центра
уже в содержимом полученной карты. Установленный helper 1.2.7 подходит.
[Разбор смещения и проверка](voyah-cluster-center-20261027.md).

Opack-67 после первого кадра восстанавливает готовность медиакарточки через
штатную службу. Исправлен сценарий «карта → статусы автомобиля → медиакарточка»,
в котором раньше появлялись загрузка и «Сб. связи». После установки повторите
этот цикл 2–3 раза. Дополнительные команды ADB и обновление helper 1.2.7 не нужны.
[Проверка возврата карты](voyah-cluster-return-20261027.md).

## 9. Обновление и восстановление

Обычное обновление: `install -r` APK с той же подписью. Совместимый helper после
каждого APK переустанавливать не требуется. Для новых подписей радио нужен
однократный переход с 1.2.1 на 1.2.2: повторите `-Mode Install`, затем `-Mode Status`.
Старый helper 1.2.1 сохраняет совместимость с полным экраном opack-59.
Для пробного режима карты нужен однократный переход на helper 1.2.7;
после каждого обычного обновления APK повторять установку не требуется.
При переходе с 1.1.2/1.2.0 или несовместимости также повторите установку помощника.

| Задача | Режим root-helper.ps1 |
| --- | --- |
| Прочитать состояние | `Status` |
| Запустить уже установленный helper вручную | `Start` |
| Включить/выключить будущий автозапуск | `EnableAutoStart` / `DisableAutoStart` |
| Остановить текущие собственные процессы | `Stop` |
| Восстановить оригинальный boot-сценарий из проверенной копии | `RemoveAutoStart` |

В командах сохраняйте `-Adb $adb @helperTarget` из раздела 1: `-Serial` добавляется
только при выборе устройства. Выключение автозапуска действует
на следующие загрузки. Перед остановкой отключите полноэкранные опции и патч радио в приложении.
`Stop` не удаляет boot-entry: при включённом автозапуске helper вернётся после загрузки.
Для завершения отката также выполните `RemoveAutoStart`; приватные backup/журналы
вручную удалять не нужно. Подробности — [VOYAH_ROOT_HELPER.md](VOYAH_ROOT_HELPER.md).

Если шаг не подтверждён, сохраните отчёт скрипта
`build/voyah-root-helper/<запуск>/report.txt`, отчёт окна и диагностику приложения.
При отсутствии кнопок Ultra сначала проверяйте тему и MFi4; при отсутствии управления —
WRITE_CANBUS и OEM-совместимость; при отсутствии полного экрана — helper и мост Tweaks.

В opack-50 добавлены точные CAN/Signal APK ПИ H97c OTA7.0_1030-86, полученные
для анализа. Другие ПИ-прошивки автоматически не разрешаются. При этой ошибке
сравните SHA-256 из диагностики с [отчётом ПИ](voyah-pi-can-20261026.md).
Root-helper и штатное радио проверяются отдельно от совместимости CAN-служб.
В opack-51 для этой комплектации ПИ скрыт подогрев руля; вход в настройки удержанием
переносится с отсутствующей кнопки на подогрев водительского сиденья.
