# Проверка кнопки трубки — opack-99

**Тест заменён [opack-100 с фоновым запуском](voyah-phone-probe-receiver-20261102.md).**
В opack-99 запуск диагностической Activity мог показывать меню VoyahPlay;
полученные пустые журналы не подтверждают исполнение команды iPhone.

По выгрузке `Voyah-compatibility-20261102-160153-880a2e9c.zip` подготовлена
диагностическая APK. Постоянного назначения кнопки ещё нет: нужно подтвердить
на экране, что iPhone открывает именно «Недавние» CarPlay.

[Комплект APK + ADB + запуск двойным щелчком](../build/phone-key99-20261102/release/VoyahPlay-phone-key-opack-99-with-ADB.zip).
Основной установочный комплект opack-98 / helper 1.2.16 сохранён.

## Что проверить

На стоящем автомобиле, без активного звонка:

1. Распаковать весь ZIP и подключить автомобиль по ADB.
2. Запустить `INSTALL.cmd`. Обновление APK прервёт CarPlay. Затем открыть
   VoyahPlay и дождаться подключения iPhone.
3. Запустить `OPEN_RECENTS.cmd`. Он отправляет только запрос открытия списка
   на основном экране CarPlay, без команд ответа, отбоя или набора номера.
   Зафиксировать, что открылось. `RECENTS_DELIVERED=true` в журнале подтверждает
   отправку, но не правильное отображение нужной вкладки iPhone.
4. Если «Недавние» открылись, вернуться в карту или меню CarPlay, запустить
   `WHEEL_TEST.cmd` и дождаться строки «Тест готов». Нажать трубку один раз.
   Сравнить результат: «Недавние» CarPlay или штатная Bluetooth-звонилка.
5. После окончания 30 секунд проверить, что короткое нажатие вновь работает
   штатно. Для досрочной остановки предусмотрен `STOP_TEST.cmd`.
6. Передать результат на экране и папку `logs` из комплекта.

При нескольких устройствах ADB запуск предлагает выбор. Serial нужен только
при ручном выборе конкретного устройства; ADB включён в комплект.
Root-helper и Tweaks повторно устанавливать не требуется.

## Что показал присланный архив

SHA-256 архива:
`0cdab4beafcf021273dd90c885104a4679c038e41b57d51039b1396f9aea6f9e`.
Все 15 полученных бинарных файлов сверены с размерами и SHA-256 из `summary.json`.
Android 11, RU-прошивка 650, экран 1920×720. Root доступен; отсутствующих файлов нет.

`wheel-events.txt` содержит `EVENT_COUNT=0`, снимки фокуса пустые. Пользователь
подтвердил, что во время записи трубка открывала штатную звонилку. Пустая запись
не доказывает отсутствие события: текущий источник наблюдения его не показал.

Получены реальные файлы, которых раньше не было:

| Файл | SHA-256 |
| --- | --- |
| KeyManager APK | `c3f7ef1ec78724ed31f70e2fc1204eff8d723d32be7b9b03b310c239c66e96fe` |
| Bluetooth Phone APK | `cb77dac341f92fe83014c104edf8c5d375a103a1ff8a7264ddbe7ca622dc25f3` |
| QGAPI.jar | `e46d3e5db0cf932cd3a39654a2f95620f2668ada8fb32b904c1684f936eca510` |
| Tweaks keymanager.bin | `251e04dc2e878a1190c842832d01f5a2f0ddaad7de4122f901da31f50a373a9d` |

В KeyManager обнаружены перехватчики `EventListenerSink` с приоритетом этапа 64,
перед штатным `KtQGSink` с приоритетом 32. Перехватчики приложений сортируются
по убыванию их приоритета. Возврат `true` из callback прекращает обычную обработку.
Кнопка 128 допускает перехват; исключены только коды 1 и 2.

Это проверено по инструкциям исходного DEX. Обычная декомпиляция метода
`EventListenerSink.onKeyEvent` ошибочно перевернула один переход, поэтому для
вывода использовался также режим fallback, а не только восстановленный Java.
Материалы находятся в `build/wheel-phone-20261102/`: полученные файлы,
`keymanager-sources`, `bluetooth-sources`, `EventListenerSink-bytecode.java`.

Штатный путь `PhoneStart` вызывает `launchApp("bt_phone")`. Bluetooth Phone
обрабатывает код 128 при коротком нажатии: отвечает, завершает вызов либо
открывает свою звонилку в зависимости от состояния. Поэтому тест не трогает
кнопку при наличии звонка CarPlay.

`keymanager.bin` имеет контейнер LBIN. Он сохранён как исходный файл и не
заменяется. Тест использует штатный Binder API, без нового Frida-hook.

## Ограничения теста

- Запуск доступен через отдельный debug-компонент с разрешением
  `android.permission.DUMP`. Обычные сторонние приложения его запустить не могут.
- Перехват регистрируется только при точном совпадении KeyManager и QGAPI
  с двумя проверенными SHA-256. Неизвестная прошивка отклоняется.
- В течение 30 секунд регистрируются числовые коды и действия клавиш после
  штатного преобразования. Перехватить разрешено только 128/SHORT=8192.
  Остальные кнопки, DOWN/UP и длинное нажатие проходят дальше.
- При звонке, смене сессии iPhone, остановке или истечении срока callback
  возвращает `false`. По окончании теста регистрация удаляется; при неудаче
  удаления отключённый callback всё равно пропускает события.
- Binder-callback не ждёт сетевого ответа. Он только ставит запрос в очередь;
  перед отправкой повторно проверяется исходная сессия и её основной видеопоток.
- Адрес `mobilephone-recents://` — проверяемая гипотеза для `showUI`, а не
  подтверждённый на этом iPhone контракт. До визуальной проверки постоянный
  переключатель не добавлен. Если URL не поддерживается, это отдельная задача
  от перехвата кнопки. Автоматические звонки как запасной путь не используются.

## Проверка сборки

- 44 проверки основного/дополнительного экранов и команд сессии прошли,
  включая 3 новых проверки Recents: основной UUID, отсутствие телефонного HID,
  отказ при замене телефона, пересоздании потока, закрытии контроллера.
- 5 проверок ограничений обработчика кнопки прошли.
- 5 проверок запуска с имитацией ADB прошли: отсутствие устройства, путь с
  пробелами, выбор второго устройства, ошибка `am` с кодом возврата 0 и
  отклонение старого сообщения READY.
- `:automotive:assembleDebug` и `:automotive:lintDebug` прошли.
- Обязательная общая команда CI выполнена: в shared 1771 тест, 78 прежних
  ошибок, новых ошибок относительно базового набора нет. Сохраняются 20 ошибок
  компиляции старых common-тестов и конфликт minSdk 25/28 в mobile.
- Подпись APK проверена; сертификат совпадает с opack-98. Все 55 остальных
  assets и runtime helper совпадают с opack-98 побайтово. ZIP и 12 файлов его
  манифеста проверены по SHA-256.

На автомобиле opack-99 в этом этапе не устанавливалась: ADB не видит устройство.
