# VoyahPlay 0.1.12 — переключатель TSR

Изменения поверх 0.1.11. Распаковать в корень проекта, собрать прежним способом с прежней подписью и assets. versionCode 13.

Откройте меню тестов → «Знаки скорости: прочитать TSR / ISA». При открытии автоматически читается состояние. Вверху переключатель TSR; при неизвестном значении он недоступен. По нажатию отправляется только setVehicleState(TSR_SWITCH,1/2), затем читается кэш. До результата переключатель не показывает новое положение как подтверждённое. «Прочитать» обновляет состояние, «Скопировать» копирует журнал.

Транспорт: TX58, присутствие Parcelable, ordinal 208, stable ID 277, значение 1 (вкл.) или 2 (выкл.). Ответ setter void. Формат и обработчик setIVI_AVMSet сверены с CAN APK SHA-256 96ac5182e795ad70c43c78f26b9cf29e76b59db67c2d5c09216ba1d8425c427c. Проверка хеша перед каждым соединением сохранена. Используется штатный одиночный setter, собственные CAN-кадры не формируются. ISA/ISLC, режим круиза и общие Apollo-разрешения модуль не записывает. Автовосстановления TSR при запуске нет.

WRITE_CANBUS — системное разрешение. Оно объявлено в манифесте, но обычная установка APK может его не предоставить. Без него запись блокируется с сообщением; приложение само не повышает права и не меняет системную установку. В таком случае пришлите скопированный отчёт.

Совпадение кэша с выбранным значением не доказывает аппаратного выполнения: OEM setter может обновлять кэш после отправки. Поддержку распознавания и появление знаков проверяйте отдельно. Само включение TSR не передаёт ограничения из CarPlay и может быть недостаточно для работы знаков без других штатных предпосылок.

Проверка: статическая сверка TX58, параметров, проверки разрешения, ограничений значений, XML манифеста. APK не собирался, на автомобиле не проверено.
