# Вспышка водительского дока RU — opack-86 / helper 1.2.15

На RU d6bfd312 владелец сообщил о повторном мигании дока при громкости,
климате, переключении приложений пассажира и без этих действий.

## Диагностика

Перед изменениями полная ширина была активна (`WINDOW=0,0 1920x720`),
разрешение Tweaks 1.1 продлевалось; top/status-обработчики работали без ошибок.
`voyahplay_dock_probe` отсутствовал. Действующий runtime запускал dock-guard
только для двух изученных Launcher ПИ; RU размером 51888996 байт пропускался.
VoyahPlay продолжал отправлять запрос скрытия через QGBus каждые 250 мс.
Это устраняет уже появившийся док, но допускает показ до обработки запроса.

Получен Launcher непосредственно с машины:
`/system/priv-app/Launcher-release-signed/Launcher-release-signed.apk`,
SHA-256 `745db9f151f00677fd0f0de8faf6921d9bc48150387d32936ad482dc424b5394`.
Изучены `LauncherModel`, `NavigationBarController` и `AppUtils`.
Метод `NavigationBarController.show()` устанавливает x=0 и вызывает
updateViewLayout либо запускает анимацию; `dismiss()` скрывает отдельно.
Контроллеры основного и пассажирского экранов имеют разные mScreenId/mTag.
AppUtils получает текущий компонент дисплея 0 через OEM ServiceManager.
Общая декомпиляция сообщила две ошибки в других методах; эти целевые методы
получены с телами. Вывод декомпилятора сохранён для проверки.

Короткая проверка процесса без установки перехватов подтвердила:
`SHOW_MODIFIERS=1`, локальной замены show нет, текущая Activity —
CarPlayHostActivity. Основной контроллер: screen=0,
tag=MainNavigationBarController, x=-145, parent=null; пассажирский — screen=1,
x=0, окно присоединено. Проверка завершена, временный скрипт удалён.

## Изменение

Dock-guard поддерживает точный RU-контроллер наряду с прежним классом ПИ.
Вызов show подавляется до отрисовки только при совпадении всех условий:

- основной дисплей и точное имя его контроллера;
- контекст штатного Launcher;
- актуальная Activity на дисплее 0 — CarPlayHostActivity или DiPlayActivity;
- действующее короткое разрешение ширины и свежий probe Tweaks 1.1;
- готовность и подписка Tweaks подтверждены исходным мостом.

HOME, другие Activity, камера, пассажирский док, ошибки определения окна,
снятие/истечение разрешения сохраняют штатный вызов show. Существующие чужие
замены метода не перезаписываются. Runtime разрешает RU только с указанным
SHA-256 Launcher и проверенной парой RU services.jar/SystemUI; проверки injector,
моста, UID процесса и приватных файлов сохранены. OEM-файлы не переписываются.
Версия probe 1.1 дополнена `profile=RU|PI`.

## Установка и аппаратная проверка

Opack-86 и helper 1.2.15 установлены на RU с сохранением данных.
Автозапуск включён, системный раздел read-only. Работающий helper сообщает 1.2.15;
BOOT_HELPER_VERSION=1.2.13 относится к последней загрузке, до этого обновления.
В живом Launcher установлен профиль RU без конфликта; первый сохранённый снимок
после обновления показал calls=8, blocked=7, active=true, ошибки пустые.
Показ верхнего статус-бара продолжает подавляться своим отдельным обработчиком.
30 октября владелец ответил «Мигание исчезло» на проверку громкости,
открытия/закрытия климата и переключения приложений пассажира после установки
opack-86/helper 1.2.15. Устранение симптома на этой RU подтверждено по экрану.
Это подтверждение не распространяется автоматически на другие прошивки.

Дополнительно выполнен переход на штатный Launcher дисплея 0 и обратно.
В меню текущий компонент стал MainActivity, защита снялась (active=false),
окно MainNavigationBarController было показано в x=0 шириной 145; это
подтверждено dumpsys и снимком home.png. После возврата компонент снова
CarPlayHostActivity, защита активна, окно штатного дока отсутствует.
Полная ширина 1920×720 восстановлена, изображение CarPlay видно (return-late.png).

Проверить громкость, открытие/закрытие климата, переключения пассажира и ожидание
в CarPlay. Затем выйти в штатное меню и вернуться: штатный док должен появиться
в меню и скрыться в VoyahPlay. Для другой прошивки требуется проверка её файлов.
