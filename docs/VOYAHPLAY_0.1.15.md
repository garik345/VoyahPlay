# VoyahPlay 0.1.15 — изменённые файлы относительно 0.1.14

## Установка

Наложите содержимое `VoyahPlay/` из ZIP на корень своего проекта VoyahPlay. Содержимое `Voyah-Diagnostics/` относится к отдельному проекту диагностики 0.3.3 → 0.3.4. Не смешивайте два каталога. Сохраните свои applicationId, подпись и существующие local-auth; они не входят в архив и не изменялись. Если mobile/build.gradle.kts у вас настроен иначе, перенесите только versionCode=16 и versionName=0.2.13-voyahplay.0.1.15 вместо замены своих настроек.

## Проверка состояний — на стоянке

1. Откройте в настройках трансляции «Voyah: тесты и диагностика» (или тесты приборной панели с главного экрана) → «Сиденья, руль, свет, ароматизатор: запись» → «Записать 2 мин».
2. Перейдите в штатные настройки. Для одного сиденья последовательно проверьте подогрев и вентиляцию: выкл → 3 → 2 → 1 → выкл. Удерживайте каждое состояние минимум 5 секунд. Другие функции оставляйте неизменными.
3. Вернитесь → «Отчёт / остановить» → «Поделиться». Сохраните запись **до следующего запуска**, который заменит её. Повторите отдельно для пассажирского сиденья, затем для массажа (вкл/выкл, интенсивности, обе программы).
4. Отдельной записью проверьте руль, режимы света и каждый аромат. Укажите порядок переключений и подпишите названия ароматов из штатного меню. Не меняйте интенсивность ароматизатора во время сравнения ароматов.
5. В отдельной диагностике 0.3.4 можно вместо этого нажимать «Читать CAN» после каждого изменения и сохранять общий JSON. Новая группа: method=getVehicleStateComfort. Данные только читаются.

У каждого снимка в VoyahPlay есть начало/конец чтения в Unix-миллисекундах. Поля читаются последовательно; снимок не атомарный. Кэш может запаздывать и содержать последние команды, а не обратную связь. Наличие полей не подтверждает работоспособность соответствующего оборудования. Запись ограничена 60 снимками/2 минутами, не является фоновым сервисом и может оборваться при уничтожении процесса Android.

## USB-микрофон

1. С настройкой «Выбор Android» подключите USB, запустите Siri, произнесите фразу. Отдельно проверьте звонок; сохраните диагностический отчёт сразу после опыта.
2. В меню тестов → «Микрофон: выбор входа» выберите встроенный. Завершите Siri/звонок и запустите заново. Повторите и сохраните отчёт. Если нового потока не было, переподключите CarPlay.
3. Для сравнения проверьте Wi-Fi. Если предпочтение ухудшает работу, верните «Выбор Android».

В отчёте нужны строки Microphone: inputTypes, preferredInputType/accepted, start, stats, failure. Счётчик udpSent означает отправку локальным сокетом, не подтверждённое получение iPhone. По умолчанию аудиомаршрут не меняется. Это диагностический обход возможного выбора неверного входа, а не установленное исправление USB.

## Панели

В настройках включите скрытие статусной и навигационной панелей. Откройте CarPlay и проверьте обе полосы. Если видны, откройте «Экран: состояние системных панелей», скопируйте отчёт и приложите фото. При возможности:

```powershell
adb shell dumpsys window > voyah-window.txt
adb shell dumpsys display > voyah-display.txt
adb shell dumpsys activity activities > voyah-activities.txt
```

Снимок Insets относится к Activity, из которой вызван тест. Запускайте его из CarPlayHost, когда проверяете трансляцию. Вход из трансляции: настройки → «Voyah: тесты и диагностика». Скрытие OEM-полос пока не подтверждено. Настройки многоконного режима не обходятся, системные процессы и глобальные настройки не меняются.

## Проверки поставки

Статическая сверка всех 33 пар ordinal/stable ID с дизассемблированным VehicleState из CAN APK владельца; проверка разрешений и ограничений RPC диагностики. Полная компиляция APK и аппаратные испытания здесь не выполнялись: JDK/Android SDK в рабочем окружении отсутствуют.

Панель девяти кнопок пока в спецификации README; эта версия собирает данные для достоверной индикации. Ключи CarPlay и подключение транспорта не изменялись.
