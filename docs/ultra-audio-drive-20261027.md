# Расширение CarPlay Ultra: звук и режимы автомобиля

27.10.2026. Подготовленная ревизия `opack-68-audio-drive-controls`, automotive/debug.
Автомобиль недоступен, по просьбе пользователя изменения подготовлены без установки.
Последняя аппаратно проверенная версия — opack-67. Root-helper 1.2.7 не меняется.

## Что вошло в APK

| Функция | Реализация | Ограничение проверки |
| --- | --- | --- |
| Навигация | Отдельный CAF Volume, вид 1, штатный поток 1 | Требуется проверить на автомобиле |
| Телефон | CAF Volume, вид 2, штатный поток 6 | Захват микрофона и маршрутизация звонка не менялись |
| Siri | CAF Volume, вид 3, штатный поток 22 | Требуется проверить на автомобиле |
| Рингтон | Подписанный пользовательский CAF Volume, вид 6, штатный поток 2 | Специальный CAF enum для рингтона не установлен; подпись локализована |
| Режим движения | Эко, комфорт, спорт, внедорожный, индивидуальный, снег | Используется проверяемый пакет OEM TX77 и чтение результата TX57 |
| Силовая установка | Smart, электро, гибрид, сохранение заряда | OEM `IVI_SOC_MODESET` 1, 2, 3, 4 соответственно |

Основная громкость и mute сохраняют реализацию opack-53, проверенную на автомобиле.
Дополнительные каналы читаются через установленный SDK `qg.audio_policy`,
дескриптор `com.qinggan.audiopolicy.IAudioPolicyService` проверяется.
Используются штатные индексы и максимумы; пересчёта в 100 ступеней нет.
Чтение/запись громкости не запрашивает аудиофокус, не включает воспроизведение,
не снимает mute других каналов и не меняет настройки микрофона.
При отсутствии подходящего SDK или валидных диапазонов дополнительные регуляторы
не объявляются. Состав и диапазоны фиксируются для сессии; после изменения
возможностей прошивки понадобится новое соединение iPhone.

## Режимы: команда и подтверждение

Команды доступны только через уже существующее разрешение WRITE_CANBUS и
проверку SHA-256 CAN APK RU/ПИ. Дополнительно перед новым TX77 сверяются
имя, ordinal и стабильный ID каждого поля с установленным OEM VehicleState.
Пакет режима движения содержит `DRIVING_MODE_SET`, `EPS_MODE_SET`,
`PROP_MODE_SET`. Таблица соответствует локально изученному
`VoyahTune/Native/.../DriveModeCanPolicy.java`:

| Режим | DRIVING | EPS | PROP |
| --- | --- | --- | --- |
| Эко | 1 | 2 | 1 |
| Комфорт | 2 | 2 | 2 |
| Спорт | 3 | 3 | 3 |
| Внедорожный | 4 | 2 | 3 |
| Индивидуальный | 5 | Сохранённый профиль | Сохранённый профиль |
| Снег | 6 | 2 | 2 |

Индивидуальные параметры читаются для текущего OEM аккаунта из
`content://qinggan.settings/global`, ключи `drive_mode_steeringWheelAssist` и
`drive_mode_runState` с суффиксом аккаунта. Если аккаунт/провайдер недоступен,
команда не отправляется. Сохранённый профиль не перезаписывается.
Дополнительные команды ароматизатора, подсветки и рекуперации не добавлены.

Нулевой ответ TX77 означает только принятие. Успех CAF выдаётся после совпадения
всех полей пакета при обратном чтении. Совпадение одного DRIVING при несовпадении
EPS/PROP не подтверждает команду. При ошибке текущее фактическое состояние
остаётся доступно, но запрос не подтверждается. На чтении/подписке записей нет.

На изученной H97C сохранение заряда (4) — штатный режим, связанный с использованием
топлива. Это не команда принудительного запуска двигателя. Гибрид имеет значение
3, а не 1: значение 1 — Smart. Принудительный электро (5) не предлагается
как обычный электро и не переименовывается в него; вне поддержанных значений
регулятор сообщает отсутствие поддерживаемого значения.

## Что пока не реализовано

| Запрошенный пункт | Чего не хватает для рабочей реализации |
| --- | --- |
| Изображение автомобиля в климате | Сопоставления `CAFVehicleVariant`/vehicle layout с ресурсами темы. Архив картинок CAF для иконок настроек сам по себе не задаёт изображение кузова в климате |
| Эквалайзер | Штатных настроек данной прошивки: диапазонов и смысла полос/пресетов. В SDK найдены getEQMode, getEQModeByIndex, getMaxBandIndex, getMaxBandValue, setBandValue и setEQMode; одних имён методов недостаточно для объявления корректных регуляторов |
| Яркость дисплеев | Штатной схемы для основного и пассажирского экранов и проверки обратного чтения. Общая Android SCREEN_BRIGHTNESS не доказывает независимое управление обоими дисплеями Voyah |
| Paired iPhones во встроенных настройках Ultra | Проверенных числовых типов CAFPairedDevices, его сервисов/характеристик/команд и формата списка/состояний. Runtime-заголовки подтверждают функции connect/disconnect/forget, но не дают этих числовых значений |

Эти пункты не объявляются фиктивными элементами. Paired iPhones не заменён
переходом в Android-настройки VoyahPlay. Для дальнейшей проверки эквалайзера
и яркости нужны APK `com.qinggan.app.setting`, установленная аудиослужба
и журнал их штатной работы либо подключённый автомобиль. Для пунктов CAF
нужна проверенная схема/реализация соответствующих сервисов или данные framework.

## Локальные проверки

- Профильный набор: **487 тестов**, common 192, shared 295, без ошибок и пропусков.
- Проверены независимость каналов, запрет записи вне диапазона, сбой/восстановление
  службы, неверное обратное чтение, повторное подтверждение неизменного значения,
  отдельная давность аудиоданных, отсутствие коллизий IID.
- Проверены связанные параметры всех режимов, отказ от выдуманного индивидуального
  профиля, запрет подтверждения частично выполненной команды, сохранение отсутствия
  обогрева руля на ПИ. Новые строки добавлены во все восемь локалей.
- `:automotive:assembleDebug` проходит. Обязательная полная CI-проверка записана
  в `build/ultra-controls68-20261027/full-ci.log`; результат сравнивается с
  неизменёнными ошибками проекта, профильный набор их не скрывает.
  Результат: те же 78 падающих shared-тестов, 20 ошибок компиляции common-тестов
  и конфликт minSdk mobile 25/common 28; все три неуспешные задачи совпали с opack-67.
  Новых ошибок нет. В полном shared-наборе теперь 1717 тестов.

Снимки новых экранов iPhone и аппаратная проверка ещё не выполнены. Android
разметка настроек не менялась: добавлены данные для существующих CAF компонентов.
