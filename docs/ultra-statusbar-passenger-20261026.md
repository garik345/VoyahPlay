# Вспышка верхней строки при переключении пассажирского экрана

26 октября 2026. Установлены opack-42-status-bar и root-helper 1.2.1.

## Причина

SystemUI `CommandQueue$H.handleMessage` обрабатывает завершение перехода приложения
на любом из двух экранов. Он получает обе верхние Activity, проверяет их через
`StatusBarInvisibleItem.isHit(String,int)` и вызывает
`PhoneStatusBar.setDualStatusBarVisible(main,second)`.

VoyahPlay отсутствовал в штатном списке полноэкранных приложений. При переключении
пассажирских приложений вычислялось `mainScreenVisible=true`, даже если водительский
CarPlay не менялся. Следующий QGBus-запрос VoyahPlay снова скрывал строку, но это
происходило после её краткого появления. Пример до исправления, 00:16:28–00:16:29:
CarPlayHostActivity на основном экране, Settings/SecondMainActivity на пассажирском,
три решения `mainScreenVisible=true`.

## Изменение

Приватный `status-bar.js` добавляет в OEM-предикат два точных имени Activity
VoyahPlay только на display 0. Исходный метод выполняется ровно один раз.
При действующем top-разрешении и свежих подтверждениях width/boot/license readiness
результат для этих двух окон становится true. Строка остаётся скрытой до отрисовки;
пассажирская строка, остальные приложения и исходные fullscreen-правила OEM сохраняются.

Разрешение проверяется на каждом подходящем вызове: его удаление действует сразу,
не дожидаясь периодического опроса. При ошибке чтения возвращается исходный результат.

Root-supervisor управляет отдельными процессами top/status, восстанавливает оба
и снимает их перед обновлением. Закреплены хеши injector и SystemUI APK. Идентичность
SystemUI проверяется по PID, имени и UID 1000; процессы самих SystemUI и system_server
не завершаются. Helper подтверждает готовность обоих обработчиков перед успешным
ответом `TOP_POLICY`. APK системных приложений и файлы Tweaks не заменяются.

## Проверки на автомобиле

- Восемь переходов пассажирского экрана между штатным меню и настройками.
  В интервале 00:17:53–00:18:05 зарегистрировано 12 решений:
  `mainScreenVisible=false`, `secondSccreenVisible=true`; ни одного включения
  водительской строки. Логи сохранены в `fixed-window-log.txt`.
- Основной CarPlay сохранил окно, AppBounds и SurfaceView 1920×720.
- При явном открытии штатного водительского меню строка вернулась:
  `mainScreenVisible=true`, собственный status probe стал inactive.
- Контролируемый SIGTERM только собственного status-agent: PID 4611 автоматически
  сменился на 13646. SystemUI остался PID 2421, system_server — PID 989.
- Quiesce обоих обработчиков завершился за 6.63 с; start восстановил оба процесса.
- Повторная установка APK через `install -r` сохранила helper, два agent и supervisor
  с теми же PID/временем старта. Полный экран и активные подтверждения восстановились.
