# ПИ без радиоприёмника: opack-98 / установщик 1.0.2

RADIO_LABELS_BUSY из полученного отчёта относится к нашему вспомогательному
скрипту подписей, а не подтверждает наличие радио. Прежний runtime вызывал
этот скрипт даже при выключенной функции. Скрипт сначала брал блокировку,
лишь затем проверял настройку. Поэтому ненужный компонент мог остановить
обновление helper на машине без приёмника. Совет закрыть штатное радио
для такой ПИ был неприменим.

## Что изменено

- Выключенный обработчик без сохранённого агента пропускается до запуска
  скрипта и обращения к блокировке.
- При остановке нет агента, настройка выключена и радио-процесс отсутствует —
  успешный пропуск с RADIO_LABELS_SKIPPED=disabled-no-process.
- Нет радио-пакета и состояния агента — успешный пропуск not-installed.
  Неоднозначный ответ или ошибка package manager отсутствием не считаются.
- При существующем состоянии агента сохраняются проверенная остановка,
  восстановление интерфейса и проверки PID/идентичности.
- Для известных CAN-сборок ПИ OTA7.0/OTA7.2 радио объявлено отсутствующим.
  Сохранённый старый radioEnabled=true его не включает. Переключатели радио
  и подписей станций скрыты в настройках VoyahPlay на этих комплектациях.
  Для проверенной RU радио и ручной переключатель сохранены.

## Обновление уже установленного старого helper

Одного нового runtime внутри APK недостаточно: прежний установщик вызывал
старый runtime ещё до замены снимка и снова останавливался на его радио-lock.
Поэтому установщик теперь передаёт отдельный helper-quiesce.sh. Bootstrap
копирует его в приватное root-хранилище, проверяет SHA-256 и применяет только
для остановки. Активный runtime и allowed.uid до успешной остановки не заменяются.
Временный сценарий удаляется при выходе. Новые действия сокета не добавлялись;
версия протокола/helper остаётся 1.2.16.

## Что установить

[Обновление APK и установщика к прежнему комплекту, около 22 МБ](../build/pi-no-radio98-20261102/release/VoyahPlay-opack-98-update-1.0.2.zip).

Распакуйте **все девять файлов** в уже существующую папку комплекта рядом
с INSTALL.cmd, согласившись на замену. Закройте CarPlay, запустите INSTALL.cmd,
после успешной установки перезагрузите мультимедиа и запустите STATUS.cmd.
Обновление проверено для наложения как на первоначальный комплект opack-96,
так и на его вариант с установщиком 1.0.1. Данные сопряжений не переносятся.

Для чистой установки используйте
[полный комплект opack-98 / 1.0.2 с ADB](../build/pi-no-radio98-20261102/release/VoyahPlay-opack-98-full-install-1.0.2-with-ADB.zip).

## Проверки и ограничения

Прошли 31 профильный common-тест и 40 сценариев shell/Windows-установщиков:
ПИ без пакета, выключенная функция, OEM-заглушка без процесса, наличие старого
агента, ошибка package manager, контрольная сумма/путь staged-сценария,
параллельные обращения и прежние проверки установщиков. Сохранены и просмотрены
compact/full RU и Arabic RTL макеты при fontScale=1.5.

Обязательная CI выполнена: 1768 shared, 79 падений. Из них 78 совпадают с прежними;
дополнительно упал CarHotspotAdbFallbackTest.boundedDeadlineAbortsStalledIoWithoutTakingASecondBudget
на ожидании старта задачи за одну секунду. Отдельный повтор всего этого класса
успешен. Сохраняются 20 прежних ошибок компиляции common и конфликт minSdk.
Общая CI не объявляется успешно пройденной.

Подпись APK V2 проверена. Все 25 файлов полного ZIP сверены с манифестом;
наложение обновления на оба предыдущих комплекта проверено по всем суммам.
Не относящиеся к helper assets, включая офлайн-аутентификацию, совпадают с opack-95.
