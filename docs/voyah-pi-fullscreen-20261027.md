# ПИ: root-helper отвечает, полная ширина отклонена

**Обновление 28 октября:** файлы получены, причина установлена, подготовлены
opack-71 и helper 1.2.8. [Разбор и комплект установки для ПИ](voyah-pi-fullscreen-20261028.md).
Ниже сохранён исходный отчёт до получения файлов.

В присланном отчёте помощник 1.2.7 подключён, UID клиента 10098 совпадает
с приложением, сервер работает от root. Автозапуск установлен и включён,
BOOT_RESULT=ready, системный раздел после перезагрузки доступен только для чтения.
Установка и автозапуск помощника по этим данным исправны.

Отказ возникает отдельно, при проверке `TweaksBoundsRoot.verifyFiles()`:
`TWEAKS_FILES_CHANGED: отличается проверенный файл /system/framework/services.jar`.
Эта проверка сравнивает файл с изученным вариантом RU
`0faed7ebf1094c62a4f92b4bc533bbb3c08480a2cd847567cb1cff91b2d1d045`.
Сообщение означает несовпадение эталонной суммы, а не установленное время изменения
файла. Фактической суммы этой машины в присланном тексте нет.

`HELPER_COMPATIBLE=1` относится к протоколу приложения и помощника.
`CAPABILITIES=TWEAKS_BOUNDS_1_1` объявляет поддерживаемую операцию. Оба поля
не подтверждают совместимость установленной прошивки и её моста ширины.
Границы меняются только после проверки services.jar, ss11.bin, frida-inject
и действующего состояния моста. На этой машине проверка останавливается на первом
файле, поэтому совместимость двух следующих ещё не установлена.

`WINDOW=145,45 1775x675` соответствует оставшимся штатным отступам: сумма координат
и размеров даёт экран 1920x720. Проверка отклонена до выдачи разрешения на расширение.

## Недостающие данные и сбор двойным щелчком

В ранее полученных архивах ПИ отсутствуют services.jar и файлы моста полной ширины.
По файлам навигации этот контракт проверить нельзя: там исследовалась другая служба.
Для адаптации нужно сравнить исходный services.jar и код Tweaks этой прошивки
с изученными RU, затем проверить поведение на автомобиле.

[Сборщик с ADB и START.cmd](../build/pi-fullscreen-20261027/Voyah-fullscreen-diagnostics-with-ADB.zip).
Распаковать весь архив, подключить машину по ADB, повторить ошибку в VoyahPlay
и запустить START.cmd двойным щелчком. При нескольких устройствах выбрать автомобиль.
Прислать появившийся на рабочем столе `Voyah-fullscreen-....zip`.

Сборщик читает services.jar, ss11.bin, SystemUI.apk, суммы компонентов,
неперсональные параметры прошивки и экрана, состояния трёх probe и узкую диагностику
окон VoyahPlay. Совпадающий с изученным injector определяется по SHA-256 и не
копируется повторно; отличающийся сохраняется для анализа.
Данные подключения и сопряжения iPhone не читаются. Команды не меняют системные
файлы, разрешения или настройки и не перезапускают службы/приложение.

Бинарный вывод `adb exec-out su 0 cat` копируется через BaseStream, без текстового
перекодирования PowerShell 5.1. Размер и SHA-256 каждого файла сверяются с машиной.
Неполные/неверные передачи не выдаются за нужный файл и отмечаются в MISSING.
Чтение каждого бинарного файла ограничено по размеру и времени.

До получения этих файлов код проверки прошивки и APK не изменены. Совпадение
упаковок/кода, обнаруженное ранее для службы навигации ПИ, не переносится автоматически
на services.jar и Tweaks.

## Проверки сборщика

Windows PowerShell 5.1: проверен синтаксис, запуск из папки с пробелами и кириллицей,
обработка отсутствующего устройства и передача структурированного результата.
На локальном имитаторе ADB проверены байты с NUL/невалидным UTF-8 и CR/LF,
сверка сумм, отбрасывание повреждённого файла, частичная выгрузка при недоступном
файле, отказ без root/устройства и пропуск известного injector. Проверен список
всех отправляемых команд: только чтение. К машине для этих проверок не подключались.

Материалы: `build/pi-fullscreen-20261027/`. Реальное получение файлов этой машины
и исправление совместимости полного экрана остаются следующими шагами.

Обязательный общий CI выполнен: тот же набор из 78 прежних падений shared,
