# VoyahPlay: чистая база DiPlay 0.2.19

База: `shihabal3amri/DiPlay`, тег `v0.2.19`, commit `e06a250219b2c2288948d8b4ad7203b417db0de1`.
Перенос из `garik345/VoyahPlay`, commit `66f783e`.

## Применение

Этот пакет накладывается только на чистый checkout DiPlay 0.2.19, не на старый
VoyahPlay. Распакуйте файлы в корень новой рабочей копии:

```sh
git clone --branch v0.2.19 https://github.com/shihabal3amri/DiPlay.git VoyahPlay-clean
cd VoyahPlay-clean
git switch -c voyah-clean-fork
```

После распаковки закоммитьте перенос в этой ветке. Таким образом сохраняется
общая история с DiPlay, а будущие обновления используют обычный Git merge.
Публикация в GitHub в рамках этой работы не выполнялась.

## Перенесено

- CAN: чтение статусов, сиденья, руль, ароматизатор, свет, TSR/ISA.
- Нижняя панель с цветами активных функций, ароматами и удержанием руля для
  открытия общего экрана настроек. Панель уменьшает область видео и касаний.
- Автодальний через существующий нативный HAL-мост; отображается отправленный
  запрос, не подтверждение состояния. Задний противотуманный остаётся
  недоступным до получения проверенной команды.
- Стрелки маршрута и названия треков на приборке; реальный звонок имеет
  приоритет над названием трека. Отдельного вывода звука этот модуль не имеет.
- OEM-док QGBus, чтение автомобиля в боковой панели, существующий добровольно
  устанавливаемый root-модуль полноэкранного режима и его лицензии.
- Имя VoyahPlay и прежний mobile applicationId `dev.voyah.diplay`.
  Automotive applicationId сохранён: `com.shilapi.xcertplay`.
- Обновления запрашиваются из garik345/VoyahPlay, чтобы APK DiPlay не заменил
  этот форк. Нужен собственный релиз APK с SHA256SUMS.txt.
- Для automotive оставлен явный импорт локальных authentication assets через
  `DIPLAY_AUTH_ASSETS_DIR`. Сами пользовательские authentication assets в
  пакет не включены и не менялись; используйте существующий локальный источник.

Настройки автомобиля и треков: категория «Автомобиль»; подсказки приборки:
«Навигация»; root-модуль: экспериментальные настройки экрана. Стандартный
экран настроек, элементы звонков и жесты DiPlay сохранены.

## Аудио

Точечное исключение Voyah перенесено по реализации VoyahTune, commit
`6ef9f2d6898b99d3cb167f806bfdde86ed3967a1`, для базы DiPlay 0.2.19.
Хост VoyahPlay передаёт `voyahMicrophone=true`; только поток `telephony`
получает источник VOICE_RECOGNITION, не включает MODE_IN_COMMUNICATION
и аппаратные AEC/NS. Переход с этого источника на VOICE_COMMUNICATION
для звонка Voyah запрещён. Другие типы потоков сохраняют выбор источника
upstream, включая отдельное правило Geely для Siri.

Опциональное программное эхоподавление Speex сохранено. При отказе его
процессор освобождается без включения аппаратных эффектов. Диагностика
указывает VOICE_RECOGNITION, а не старое имя источника telephony.

Микрофон изменён в AndroidMediaSink, MicrophoneUplink, MicrophoneCaptureStats
и передаче флага в хосте. Дополнительный перенос аудиоканалов описан ниже. Кодеки, RTP, Telecom,
Bluetooth и настройки соответствуют базе. Проверка границы фиксирует
SHA-256 согласованных аудиоисключений; остальные 366 файлов сравниваются
с upstream побайтово. Изменения не включают запись звука на диск.

## Проверено

  совпадают с базой; восемь аудиофайлов/тестов проверяются по SHA-256; отсутствуют ссылки на удалённые диагностические классы.
- `python scripts/check_public_tree.py`: пройдено.
- XML ресурсов и manifest корректно разбираются; git diff --check пройден.
- Проверены точки подключения панели и lifecycle, навигации и треков.

По просьбе владельца Gradle, сборка APK, Android lint и JVM-тесты не запускались.
Скриншоты Android UI и аппаратная проверка не выполнялись. Патч устраняет известный по VoyahTune выбор неисправного VoIP-тракта,
но не доказывает исправление звонка на конкретной машине.
Проверьте Siri и звонок отдельно по USB и Wi-Fi, затем приборку и панель.

Общие аудио/связные модули специально защищены проверкой границы; новые правки
для Voyah следует вносить в модули автомобиля и их точки интеграции.

## Аудиоканалы и OEM-аудиофокус

Добавлены автоматические маршруты Voyah: музыка 3, навигация 1, звонки 6,
Siri 22. Явный ненулевой выбор каналов музыки/навигации сохраняет приоритет.
Legacy AudioTrack считается пригодным только при совпадении фактического
streamType с запросом; иначе используется исходный usage-based fallback.

Фокус имеет приоритет PHONE > ASSISTANT > NAVIGATION > MEDIA. OEM-фокус
запрашивается только при подтверждённом типовом AudioTrack. Для музыки
остаётся исходный Android-фокус. Навигация держит фокус от ненулевого PCM
до его воспроизведения и 500 мс без новой подсказки. Тишина не продлевает
запрос; закрытие renderer/sink освобождает его.

VoyahAudioFocus адаптирован из Native/CarPlayAudioController VoyahTune.
В standalone он принадлежит sink, использует application context, отдельный
HandlerThread, установленный системный OEM SDK и проверку Binder descriptor.
Запросы используют package текущего APK и уникальный client ID сессии;
перезапуск одного sink не снимает запрос другого. Binder transaction numbers
не копируются. Установленный Native/VoyahTune не требуется.

Аудиофокус включается по умолчанию только при отсутствии сохранённого ключа;
сохранённый false не меняется. Для проверки включите «Аудиофокус» и
переподключите CarPlay. Отказ OEM API не останавливает Android-воспроизведение;
диагностика содержит requested/actual/accepted и OEM focus granted/unavailable.
Одинаковые номера каналов не гарантируют поддержку всех прошивок ГУ.

Проверка границы: 366 файлов upstream без изменений, 8 согласованных
аудиофайлов/тестов сверяются по SHA-256. Добавлены тесты тишины/окончания
подсказки, remapped AudioTrack и атрибутов Qinggan; reflection-тест renderer
обновлён на 14 параметров. По просьбе владельца сборка и JVM-тесты не запускались.
Аппаратно проверьте независимую громкость всех четырёх ролей, возврат кнопок
громкости к музыке после подсказки, звонок и Siri по USB/Wi-Fi.

Приглушение duckAudio/unduckAudio по командам iPhone, новые ползунки OEM-громкости,
скорость/CAN и тема по SWReason не входят в этот патч.

## Скорость и передача CAN → iPhone

VoyahCanSpeedSource читает проверенную CAN-службу: TX26 getVehicleSpeed (int,
км/ч), TX6 getGearStatus (nullable GearState; stable ID и ordinal). Значения
P=0, R=1, N=2, D=3; прочие значения неизвестны. Пакет проверяется по SHA-256
той же CAN APK, что используется остальными модулями автомобиля.

Binder/hash выполняются на одном фоне; основной поток и iAP2 не ждут чтения.
Чтение раз в секунду только после запроса vehicle speed от iPhone. Буфер
VoyahVehicleSpeedSource перенесён из VoyahTune: максимум 32 отсчёта, возраст
не более 3 секунд, строго возрастающее monotonic время, диапазон 0…300 км/ч,
преобразование км/ч / 3.6 в м/с. Смена передачи очищает старые отсчёты.
Ошибка/потеря Binder очищает буфер и инициирует перепривязку. Неизвестные
данные не подменяются нулём или передачей D. Запоздалые ответы прошлой
сессии отбрасываются. Зависший Binder не создаёт очередь новых чтений.

Штатный VehicleSpeedLocationProvider передаёт реальные отсчёты как $PASCD
через iAP2 0xFFFB, только если iPhone запросил VEHICLE_SPEED_DATA. При
выключенной отправке GPS/отсутствующем разрешении используется пустой
position provider: координат нет, скорость/передача доступны отдельно.
Поддержка заявляется iPhone при следующем подключении. Это не гарантирует,
что конкретное навигационное приложение iPhone использует эти данные.

Диагностика содержит Voyah CAN: speedKmh/gear/sampleElapsed раз в 5 секунд
и ошибки проверки/чтения. Добавлены тесты преобразования, P/R/N/D,
устаревших/будущих/повторных данных, смены передачи и остановки. Сборка,
JVM-тесты и проверка на автомобиле не запускались. Требуется переподключить
CarPlay и проверить отчёт в движении, с выключенным GPS и после остановки.

## Запрет BYD-функций

VoyahPlatformPolicy задаёт неизменяемые false для BYD OEM-интеграции и
локального ADB. Эффективные getters BydOutputSettings возвращают false;
старые preferences не удаляются и не могут обойти запрет. LocalAdb.connect
возвращает UNSUPPORTED до открытия сокета и запроса авторизации.

BYD Bluetooth suspend/resume/recovery, WifiScanPause/restore, boot repair,
call popup suppression, музыкальная подсветка, standalone HUD, ADB cluster
и поиск BYD cluster display блокируются до соответствующих операций.
BYD-разделы настроек скрыты; BYD setup wizard заменён обычной настройкой
подключения. Управление громкостью навигации через старый перехватчик руля
отключено, чтобы не конкурировать с новым OEM-аудиофокусом Voyah.

BydNavigationOutputs сохраняет локальный разбор маршрута/overlay, но не
запускает BYD службы и не выполняет OEM cleanup. VoyahNavigationOutput и
VoyahTrackOutput вызываются до BYD-запрета. Собственные CAN speed/gear,
панель, Qinggan-аудиофокус, микрофон звонка и обычные USB/Wi-Fi/Bluetooth
подключения iPhone сохранены. Автономный updater VoyahPlay не отключался.

Проверка границы фиксирует BYD guards и дополнительные исключения core;
362 исходных core/test файла совпадают с DiPlay. Добавлены регрессионные
тесты старых opt-ins, ADB approval и подсветки. Сборка/JVM-тесты не запускались;
исходные BYD-тесты могут требовать адаптации к запрещённой платформе.
На устройстве проверьте USB/Wi-Fi, Siri/звонок, CAN и собственную приборку
Voyah. Возврат по доку и системные возможности Voyah не менялись.
