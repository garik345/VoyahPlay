# Полная ширина VoyahPlay через меню

Для Voyah Free 2026 RU, Android 11, с уже установленной и проверенной добавкой
Tweaks 1.1. Проверены на автомобиле расширение через эту добавку и совместное
скрытие дока. Управление из APK с помощником 1.0.4 подтверждено пользователем. Автозапуск
помощника 1.1.0 ещё требует проверки после перезагрузки ГУ.

## Установка

Сначала выполните [установку помощника 1.1.0](VOYAH_ROOT_HELPER.md), включая
очистку старых исходников перед сборкой `automotive` и `-Mode Install` после APK.
Прежний модуль удалён из меню/APK; его payload на ГУ удаляется при миграции.
Добавку Tweaks 1.1 переустанавливать не требуется.

## Использование

В настройках VoyahPlay найдите **«Полная ширина через Tweaks»**.
В CarPlay настройки открываются длительным нажатием на кнопку «Свет».
Переключатель находится в разделе системного полноэкранного режима.

Сначала включите «Скрыть панель навигации», затем новый переключатель.
Включение подтверждается только после успешного ответа помощника.
Выбор сохраняется и применяется при следующем запуске/возврате в приложение.

При необходимости применения границ переоткрывается собственная задача
текущего окна: Android создаёт новую ActivityRecord, и существующий обработчик
Tweaks повторно выбирает границы. Используются `NEW_TASK | CLEAR_TASK`
для той же Activity. Процесс приложения продолжает работать. В VoyahPlay
предусмотрен подхват сохранённой CarPlay-сессии новым окном; это нужно проверить
для используемого подключения на мультимедиа.

Во время такого переоткрытия восстановление дока/снятие разрешения откладывается
до появления нового окна, максимум на 10 секунд. Повторный перезапуск того же
окна по кругу ограничен. При уже подходящих границах переоткрытия нет.

При выключении снимается разрешение и окно возвращается к исходной ширине.
При уходе в другое приложение разрешение снимается после короткой паузы;
быстрый переход между собственными окнами сохраняет его и соединение QGBus.
Верхняя штатная строка пока остаётся. Основные границы: `0,45–1920,720`,
исходные — `145,45–1920,720`. Для опущенного экрана нижняя координата — `530`.
Экран пассажира, приборная панель, другие приложения и freeform исключены.

## После перезагрузки мультимедиа

При включённом «Автозапуск root-помощника» помощник стартует после готовности
Android. Сохранённая полная ширина применяется при открытии VoyahPlay.
Для обычного запуска компьютер больше не требуется. Само приложение автоматически
открывается только при включённой отдельной настройке автозапуска приложения.

Если отключить автозапуск помощника и перезагрузиться, понадобится ручной
`root-helper.ps1 -Mode Start`. При обновлении кода помощника нужен `-Mode Install`.

## Проверка

| Действие | Ожидаемый результат |
| --- | --- |
| Включить режим в главном окне | Окно начинается от левого края, док скрыт |
| Перейти в CarPlay | Полная ширина сохраняется, док не перекрывает изображение |
| Открыть и закрыть настройки | Скрытие/разрешение передаются текущему окну |
| Выйти на штатный главный экран и вернуться | Док возвращается снаружи и скрывается в VoyahPlay; ширина применяется снова |
| Выключить режим | Окно возвращается к исходному отступу 145 пикселей |
| Отключить и снова подключить iPhone | Выбранный режим применяется к новому окну CarPlay |
| Проверить касания по левому и правому краю | Координаты соответствуют изображению после изменения размера |

При включении/выключении также проверьте сохранность воспроизведения,
навигационных подсказок и самого CarPlay-подключения. Тестовый скрипт Tweaks 1.1
с `-Mode Test` одновременно с включённым режимом APK не запускайте: оба управляют
одним коротким разрешением. Для повседневного включения теперь используется меню.

## Отчёт и ограничения

Кнопки «Проверить полную ширину через Tweaks» и «Скопировать отчёт полной ширины»
находятся в нижней группе действий настроек. Проверка показывает ожидание и
ответ в отдельном окне. В сообщениях различаются отправка разрешения,
его чтение добавкой (`BRIDGE_ACK=1`) и фактическая геометрия (`WINDOW=...`).
Сообщение «Полная ширина применена» формируется по координатам окна:
`WINDOW=0,45 1920x675` либо `1920x485`.

Root-помощник проверяет поддержанную версию Android, контрольные суммы
`services.jar`, добавки `ss11.bin`, существующего инъектора и свежий статус
текущего `system_server`. Его UID проверяется по `status`, процесс — по первому
аргументу `cmdline`; владелец каталога `/proc/PID` не используется как UID.
При отказе `TWEAKS_BRIDGE_PID` отчёт содержит фактические данные процесса.
Существующие условия готовности/подписки Tweaks
сохранены. Файлы другого выпуска автоматически не подменяются.

Приложение продлевает разрешение каждые 3 секунды; срок одного разрешения —
15 секунд. Вызовы root проходят через существующий сокет с проверкой UID,
произвольные команды не принимаются. Новый Frida-agent не устанавливается.

Если при выключении помощник недоступен, выбор выключения всё равно сохраняется.
Приложение ждёт до 31 секунды для истечения старого допуска и затем обновляет
собственное окно. При аварийном завершении процесса повторное применение/
восстановление выполняется уже при следующем запуске.

Дополнительный журнал:

```powershell
adb logcat -b main -b system -d -v threadtime "VoyahTweaksFullscreen:V" "VoyahDockVisibility:V" "*:S" |
    Out-File -Encoding utf8 "$env:USERPROFILE\voyahplay-fullscreen.txt"
```

Локально проверяются Java/Kotlin-компиляция против Android 11 API, протокол
помощника и статус добавки, модели управления разрешением, переходов между
окнами и root-команд. Полная сборка APK и испытание новой интеграции на
мультимедиа здесь не выполнялись.

Основание выбора способа обновления окна: Android 11
[ActivityThread](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-11.0.0_r1/core/java/android/app/ActivityThread.java),
[ActivityStarter](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-11.0.0_r1/services/core/java/com/android/server/wm/ActivityStarter.java)
и [WindowConfiguration](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-11.0.0_r1/core/java/android/app/WindowConfiguration.java).
Публичный `recreate()` использует конфигурацию клиента, а стандартный resize
ограничен оконными режимами. Новая ActivityRecord повторно проходит штатную
обработку конфигурации, в которую уже встроена проверенная добавка Tweaks.
