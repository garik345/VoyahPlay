# Штатное радио: подписи и плавность — opack-55

26 октября 2026. Проверено на подключённой мультимедиа RU через ADB.

## Что мешало работе

1. При первой проверке патч оставался выключен: `RADIO_LABELS_ENABLED=0`,
   обработчик отсутствовал. Обновление APK и установка helper сами не включают
   отдельную экспериментальную настройку подписей.
2. Фактический APK расположен в `/vendor/app/rdsapp-release-signed/rdsapp-release-signed.apk`.
   Прототип не разрешал `/vendor/app` в Java-проверке и shell-обработчике.
   Сам APK совпал с проверенным SHA-256
   `36b4d73a889aa78325f6a6ff0c8113c6b13605620a5a4b045209fbff36449cca`, UID 1000.
   Helper 1.2.4 учитывает vendor-размещение, сохраняя проверки APK, UID и injector.
3. На настоящем Java bridge `Iterator.next()` возвращает Object: перед вызовом
   методов нужен `Map.Entry`. Конструктору `SpannableString` также нужен Java
   CharSequence. Эти преобразования исправлены; моки тестов теперь воспроизводят
   реальные ограничения типов, а не предоставляют методы автоматически.
4. Одни span-размеры не уменьшали исходные метрики TextView: частота во второй
   строке обрезалась. Теперь базовый размер текста подгоняется вместе со spans
   и восстанавливается при отключении.

## Изменение для плавности

В opack-54 таймер раз в 500 мс обходил все сохранённые поля. Проверка неизменности
была слишком поздно: измерение и сокращение текста уже выполнялись на UI-потоке.
Пользователь сообщил о тормозах; это поведение удалено в opack-55.

- Подпись строится в штатном `bindView`: при открытии, прокрутке, обновлении списка
  и получении результатов поиска. Патч не вызывает повторный bind по таймеру.
- Измеренная разметка кешируется у TextView. Повторный bind той же частоты, имени
  и размеров использует её без нового измерения.
- Раз в секунду фоновый агент читает только переключатель. Если он не изменился,
  список не обходится, UI-задачи и перерисовки не создаются.
- При выключении выполняется однократный обход для отката. Если UI занят или
  восстановление не удалось, попытка повторяется; отсоединение требует сообщения
  `enabled=0 modified=0 error=` без ошибки.
- При подключении к уже открытому радио каждый из двух адаптеров однократно
  получает штатное `notifyDataSetChanged`.

Позднее RDS-имя применяется при следующем штатном обновлении карточки, а не по
полусекундному опросу. Отдельного поиска/настройки радиоприёмника патч не выполняет.
Неизвестное имя оставляет частоту; длинное сокращается в пределах OEM-поля.

## Результат на автомобиле

В списке видны Like FM / 87.9, RECORD / 89.9, RETRO FM / 88.3, ZHARA FM / 100.5
и другие пары. Частота помещается во вторую строку. Проверено восстановление
исходных частот и размера текста при отключении без перезапуска радио.

После изменения пользователь проверил прокрутку и вкладки и подтвердил:
«Да, стало плавно». Агент сообщает `version=1.1 mode=on-bind`, без ошибок Java.
Диагностический `VOYAH_RADIO_LABELS_PERF` раз в 10 секунд показывает число штатных
bind, новых форматирований и откатов; сам этот отчёт не оформляет плитки.
После окончательной установки журнал показал рост bind с 95 до 101 при неизменных
57 форматированиях; несколько последовательных отчётов также сохраняли эти значения.

Патч оставлен включённым. Автозапуск helper включён. APK радио не заменён.
Перезагрузка мультимедиа и новый эфирный поиск станций в этом сеансе не проверялись.

Снимки и журналы: `build/radio-live-20261026/`, включая `radio-font-fixed.png`,
`radio-restored-real.png`, `radio-events.png`, `events-node-tests.log` и
`events-profile-build.log`.
