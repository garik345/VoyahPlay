# Полный экран CarPlay: opack-41, 25–26 октября 2026

Установлены automotive opack-41-fullscreen и root-helper 1.2.0. На водительском
экране подтверждены окно, AppBounds и SurfaceView `0,0–1920,720`.
Штатная строка состояния и левый док скрыты, нижняя часть изображения доступна.
Все работы выполнены локально и через ADB, без обращения к GitHub.

## Причины

1. При начале диагностики приложение имело UID 10114, а root-снимок разрешал
   10113; записанный PID helper уже не существовал. Это объясняет невозможность
   воспользоваться тем помощником. Обычная установка APK через `install -r`
   в этой проверке сохраняла UID, поэтому нельзя утверждать, что любое обновление
   APK меняет UID. В прежнем launcher отсутствовало восстановление завершившегося
   процесса и доверенная автоматическая привязка после смены UID.
2. Обработчик Tweaks принудительно выбирал верхнюю границу 45 пикселей. Скрытие
   верхней строки само по себе не освобождало эту область для окна приложения.
   Пробное смещение окна вверх обрезало нижние 45 пикселей; оно удалено.
3. PhoneStatusBar этой прошивки принимает QGBus-событие
   `SYSTEMUI_STATUS_BAR_MODE_VISIBLE` только с gallery routing label.
   С реальным source VoyahPlay визуальный запрос игнорировался.

## Реализация

- Root-supervisor проверяет helper и собственный top-agent каждые пять секунд.
  Записи процессов содержат boot ID, PID и время старта; проверяются root UID
  и аргументы. Сигналы направляются только проверенным собственным процессам.
- Привязка к изменившемуся UID требует точного имени пакета и совпадающего набора
  сертификатов с приватным root-снимком APK. Приложение не запускает `su`.
- Отдельный приватный `top-bounds.js` корректирует Configuration через
  `Task.onRequestedOverrideConfigurationChanged`, только для DiPlayActivity и
  CarPlayHostActivity, display 0, fullscreen и известных границ этой прошивки.
  Нижняя граница 720/530 сохраняется. Другие приложения, passenger и freeform
  исключены. Оригинальный метод вызывается ровно один раз.
- Разрешение верхней границы действует 15 секунд, обновляется foreground-клиентом
  примерно каждые три секунды и снимается при уходе. Обработчик дополнительно
  требует свежего статуса прежней добавки Tweaks 1.1 с boot/license readiness.
- Для SystemUI используется событие с `displayId=0`, `isVisible` и gallery
  compatibility route. Messenger-клиент остаётся VoyahPlay. Системный APK,
  исходные скрипты Tweaks и их проверки лицензии не заменяются.
- При обновлении helper supervisor и собственный agent сначала останавливаются.
  Установщик ограниченно повторяет STOP при `HELPER_BUSY`, пока заканчивается
  foreground-запрос. Живые процессы с неоднозначной идентичностью не уничтожаются.
- Чтение `/proc/PID/cmdline` ограничено одним блоком и тайм-аутом: на этом ядре
  прямой `tr` мог зациклиться при исчезновении PID. После SIGTERM ожидание выхода
  проверяет время старта процесса, не перечитывая его аргументы.

## Проверки на ГУ

- Android 11, serial d6bfd312, UID приложения 10114.
- Реальная проекция CarPlay, сетка приложений и климат занимают всю поверхность
  1920×720. Проверено нажатие кнопки сетки у нижнего левого края и открытие климата.
  Настройки температуры, вентилятора, сидений и других исполнительных функций
  при этих тестах не изменялись.
- HOME возвращает штатный док/верхнюю строку, удаляет собственное top-разрешение
  и снимает width lease. Возврат в VoyahPlay восстанавливает полный экран.
- Повторные `install -r` сохраняют UID, оба переключателя скрытия и процессы helper,
  agent, supervisor. После запуска возвращается полная проекция.
- Контролируемый SIGTERM helper: PID 8958 заменился на 15242. Аналогичный тест
  agent: 9115 заменился на 15627. Оба восстановились автоматически.
- Обновление самого helper при открытом CarPlay прошло после ожидания занятых
  запросов. Итоговый отчёт: `HELPER_VERSION=1.2.0`, `HELPER_READY=1`,
  `AUTOSTART_ENABLED=1`, `BOOT_MOUNT_READ_ONLY=1`.
- Прямой quiesce окончательного runtime завершился за 2.42 с; последующий start
  восстановил agent/supervisor без перезапуска CarPlay или Android.
- PID system_server оставался 989. Контрольные суммы оригинального injector,
  ss11.bin и services.jar совпали с закреплёнными значениями.

## Автоматические проверки

Профильный прогон: 177 тестов, 0 ошибок; включает пять новых root-проверок.
`node scripts/tests/test-top-bounds.cjs`: 9 проверок, все прошли. Проверены область
действия, срок разрешения, boot/license gates, чужие окна, ошибки инспекции
и обязательный вызов оригинального метода. Android shell проверил синтаксис runtime.

Проверены compact/full снимки экрана подготовки при fontScale 1.5, включая Arabic RTL.
APK собран и подписан прежним debug-сертификатом.

Обязательная команда из AGENTS.md выполнена с дополнительным automotive assemble.
Итоговый общий прогон: 1698 shared-тестов, 78 падений; список полностью совпадает
с `build/info-latency-20261024/full-shared-failures.txt`, новых или исчезнувших нет.
Остаются прежние ошибки компиляции старых common-тестов и конфликт minSdk
mobile=25/common=28. Общий CI не зелёный; профильные проверки и automotive build успешны.
